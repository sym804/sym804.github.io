E2E 테스트 전 빌드

빌드 산출물을 대상으로 E2E 테스트를 실행하는 구성에서는 소스를 수정해도 다시 빌드하지 않으면 이전 번들로 테스트가 실행된다.

노하우난이도 기초웹 프론트엔드최종 업데이트 2026-11-24

증상

섹션 제목: “증상”
  • 소스를 수정해도 E2E 결과가 변하지 않음. 수정이 잘못된 것으로 오인하기 쉬움
  • CI에서 E2E 단계가 The directory "dist" does not exist로 실패함

원인

섹션 제목: “원인”

Playwright 설정의 webServer.command가 vite preview, next start, astro preview처럼 빌드 산출물을 서빙하는 명령이면, 테스트 대상은 소스가 아니라 마지막으로 빌드한 번들(빌드 산출물)이다.

  • 로컬: 다시 빌드하지 않으면 이전 번들로 테스트를 실행함
  • CI: E2E 단계가 build 단계 앞에 있으면 실행 시점에 번들이 없음
  • reuseExistingServer: !process.env.CI이면 로컬에서 이미 실행 중인 이전 서버를 재사용함

조치

섹션 제목: “조치”
  • 로컬과 CI 모두 E2E 전에 build를 실행함
  • CI 단계 순서: install -> test -> build -> playwright install -> test:e2e
  • E2E가 예상과 다르게 실패하면 소스를 수정하기 전에 번들이 최신인지 먼저 확인함
    • webServer.command가 빌드 산출물을 서빙하는 명령(preview 등)인지 개발 서버(dev)인지부터 확인함
    • 산출물 폴더의 수정 시각과 마지막 소스 수정 시각을 비교함

규칙

  • 이전 빌드 산출물로 실행된 테스트의 실패는 테스트 코드나 제품 결함과 구분해 실행 환경 원인으로 분류함

현장 노트

  • 같은 원인의 실패가 한 시간 안에 두 번 발생한 사례가 있음. 처음에는 로컬에서 빌드하지 않았고, 두 번째에는 그 원인을 찾은 직후 CI에 E2E 단계를 추가하면서 build 앞에 배치함

관련 문서

자동화E2E 실패 분류Playwright 실패를 산출물 근거로 원인별로 분류하는 방법. 원인 분류 체계를 고르는 기준, 결과 상태 확인, 산출물 확인, 재현 순서, 결과 기록 기준을 다룬다. 분류는 수정보다 먼저 수행한다.

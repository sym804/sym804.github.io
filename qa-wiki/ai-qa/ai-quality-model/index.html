AI 시스템 품질 모델(ISO/IEC 25059)

ISO/IEC 25059:2023은 25010 품질 모델에 AI 시스템 고유의 부특성을 추가하거나 수정한 확장 모델이다. AI 기능의 품질 요구사항과 테스트 범위에서 빠진 항목을 확인하는 기준으로 사용한다.

기본기난이도 심화AI 제품최종 업데이트 2026-11-24

25059는 AI 시스템의 판단 대행, 잡음이 있거나 불완전한 데이터의 사용, 확률적 동작, 운영 중 적응을 고려해 기존 품질 모델의 부특성을 추가하거나 수정한다. 수정하지 않은 특성은 25010 정의를 그대로 따른다. 제품 품질과 사용 품질 두 관점으로 구성된다.

추가·수정된 부특성

섹션 제목: “추가·수정된 부특성”

제품 품질

  • 사용자 통제성(User controllability): 사람이나 외부 주체가 AI 시스템의 동작에 적시에 개입할 수 있는 성질. 사용성의 신규 부특성임
  • 기능 적응성(Functional adaptability): 배포된 환경의 변화에 맞춰 스스로 적응하는 능력. 새 학습 데이터, 운영 데이터, 이전 결과로부터의 학습을 포함함. 기능 적합성의 신규 부특성임
  • 기능 정확성(Functional correctness): 필요한 정밀도로 정확한 결과를 제공하는 정도. 정의는 25010:2011과 같고, AI 시스템은 모든 상황에서 기능 정확성을 보장하지 않는다는 주석이 추가됨
  • 견고성(Robustness): 어떤 상황에서도 기능 정확성 수준을 유지하는 정도. 처음 보는 입력, 편향·적대적·잘못된 입력, 외부 간섭, 환경 조건을 포함함. 신뢰성의 신규 부특성임
  • 투명성(Transparency): 관련 이해관계자에게 AI 시스템에 관한 적절한 정보를 전달하는 정도. 결과의 근거뿐 아니라 적용 한계, 구성, 모델, 데이터, 검증 정보를 포함함. 사용성의 부특성임
  • 개입 가능성(Intervenability): 운영자가 위해나 위험을 예방하도록 적시에 개입할 수 있는 정도. 시스템 상태를 관찰하고 안전하지 않은 상태에서 안전한 상태로 전환하는 것을 포함함

사용 품질

  • 사회적·윤리적 위험 완화(Societal and ethical risk mitigation): AI 시스템이 사회에 미칠 수 있는 위험을 완화하는 정도
  • 투명성(Transparency): 사용 품질의 만족(Satisfaction)에 속하는 부특성임

위 정의는 표준 원문을 요약한 내용이다. 상위 특성 이름은 25010:2011 기준이며, 2011판의 사용성은 2023판의 상호작용 능력에 해당한다.

판 확인

섹션 제목: “판 확인”

25059:2023은 ISO/IEC 25010:2011을 인용 규격으로 삼는다. 2023년에 개정된 25010(특성 9개, 사용성은 상호작용 능력으로 변경)과는 이름이 다른 부분이 있다. 25059의 개정판이 진행 중이므로 인용 시점의 판을 확인한다.

부특성별 점검 항목과 TC 예시

섹션 제목: “부특성별 점검 항목과 TC 예시”
부특성 요구사항 리뷰에서 확인할 항목 TC 예시
기능 정확성 정답 인정 기준, 목표 정답률
평가셋 구성과 버전		 평가셋 전체를 질의별 3회 실행해 정답 조건 충족률이 목표 이상인지 확인함. 정답률과 오답 유형별 비율을 따로 기록함
견고성 오타·줄임말·다국어 입력 처리
지시를 바꾸려는 입력 처리		 평가셋 질의에 오타, 동의어, 무관한 문장을 추가한 변형 세트를 실행해 원래 세트 대비 정답률 하락이 허용 범위 안인지 확인함
투명성 근거 표시 방식, 답할 수 없는 범위 안내
모델·문서 갱신 시점 공개		 답에 표시된 근거 문서와 조항을 열어 답의 내용과 일치하는지 확인함. 범위 밖 질문에 안내 문구가 표시되는지 확인함
사용자 통제성 생성 중단, 답 신고, 자동 실행 끄기 답 생성 중 [중단]을 클릭해 추가 출력이 멈추는지, 이미 실행된 도구 호출의 결과가 어떻게 처리되는지 명세와 대조함
개입 가능성 기능 즉시 차단 절차, 특정 문서 제외 절차
이상 상태 관찰 수단		 관리자 설정에서 AI 응답을 끄면 재배포 없이 기존 검색 화면으로 전환되는지 확인함
기능 적응성 새 정보를 반영하는 방식과 주기
반영 뒤 검증 절차		 개정된 규정으로 답이 바뀌어야 하는 질의와 바뀌면 안 되는 질의를 함께 실행해 두 조건을 모두 확인함
사회적·윤리적 위험 완화 민감 주제의 응답 범위
집단별 결과 차이, 사람 담당자 연결		 같은 질문에서 이름·성별·부서만 바꾼 입력의 답을 비교해 결과 차이가 없는지 확인함

관련 위키 문서: 기능 정확성은 LLM 기능 테스트와 LLM 평가셋과 LLM 심판, 견고성의 적대적 입력은 LLM 보안 테스트, 투명성의 근거 일치는 RAG 테스트.

적용 예: 사내 문서 질의응답 기능의 요구사항 리뷰

섹션 제목: “적용 예: 사내 문서 질의응답 기능의 요구사항 리뷰”

기획서에 “사내 규정 문서를 근거로 직원 질문에 답하는 챗봇을 추가한다”만 있는 경우, 25059 부특성을 대응시키면 기획과 확인할 항목은 다음과 같다.

  • 기능 정확성: 정답으로 인정할 기준(근거 문서 일치, 필수 정보 포함), 목표 정답률과 측정용 평가셋, 허용하는 오답 유형
  • 견고성: 오타, 줄임말, 영어가 섞인 질문, 규정에 없는 질문, 지시를 바꾸려는 입력에 대한 동작 기준
  • 투명성: 근거 문서와 조항 표시 방식, 답할 수 없는 범위의 안내 문구, 사용 모델과 문서 갱신 시점 공개 여부
  • 사용자 통제성: 생성 중단, 답 신고, 사람 담당자 연결 기능의 제공 여부
  • 개입 가능성: 잘못된 답이 퍼질 때 기능을 끄거나 특정 문서를 검색 대상에서 즉시 제외하는 절차
  • 기능 적응성: 시스템이 새 정보를 스스로 반영하는지, 운영자가 색인을 갱신하는 방식인지의 구분과 반영 뒤 검증 절차
  • 사회적·윤리적 위험 완화: 인사·징계 규정 같은 민감한 질문의 응답 범위, 다른 부서 문서의 노출 차단 여부

정답률 목표, 응답 범위, 중단 절차가 정해지지 않으면 TC의 기대 결과를 작성할 수 없다. 이 항목들은 테스트 착수 조건으로 관리하고, 합의된 값을 요구사항 문서에 반영한 뒤 TC를 작성한다.

테스트 계획, 결함 분류, 보고에 적용

섹션 제목: “테스트 계획, 결함 분류, 보고에 적용”

테스트 계획

  • 기능 정확성 목표와 함께 개입 가능성(즉시 차단 절차)과 사용자 통제성(중단·신고)을 출시 조건에 포함함
  • 평가셋 버전, 모델 이름과 버전, 프롬프트 버전, 색인 시점, 반복 실행 횟수를 측정 조건으로 계획서에 기록함

결함 분류

  • AI 결함을 “오답” 하나로 묶지 않고 부특성으로 나눔. 사실 오류는 기능 정확성, 인용 불일치는 투명성, 입력 변형 시 실패는 견고성, 중단·차단 실패는 사용자 통제성이나 개입 가능성
  • 부특성별로 집계하면 수정 위치(프롬프트, 검색, 가드레일, 화면)를 정하기 쉬움

품질 보고

  • 정답률 하나로 보고하지 않고 부특성별 결과와 미검증 범위를 함께 보고함. 예: “기능 정확성: 평가셋 v3 기준 목표 달성 / 견고성: 변형 세트 정답률 하락 허용 범위 안 / 개입 가능성: 차단 절차 확인 / 사회적·윤리적 위험 완화: 미검증”
  • 보고서에 측정 조건(평가셋·모델·프롬프트·색인 버전)을 함께 기록함. 조건이 다르면 이전 회차 결과와 비교하지 않음

현장 노트

  • 지시만으로 통제되지 않은 사례: 외부 모델에 “검증만 하라”고 지시했으나 쓰기 권한이 열린 환경에서 실행되어 코드 9개 파일 수정, 커밋·푸시, 이슈 7건 등록까지 수행함. 사용자가 원하는 동작 범위를 지시문으로만 정하면 통제가 보장되지 않아, 이후 검증용 실행은 읽기 전용 샌드박스로 강제함. 제품의 사용자 통제성과 개입 가능성도 지시문이 아니라 실제로 동작하는 장치로 확인해야 하는 근거임(AI 에이전트 권한 통제)

규칙

  • AI 기능의 품질 요구사항은 25010 특성과 25059의 추가·수정 부특성을 함께 점검함
  • 사용자 통제성과 개입 가능성은 화면 문구가 아니라 실제 동작으로 판정함. 사용자 조작이 동작을 멈추거나 되돌리는지, 운영자 개입이 시스템을 안전한 상태로 전환하는지 확인함

흔한 실수

섹션 제목: “흔한 실수”
  • AI 기능을 기능 정확성 하나로만 평가함. 통제, 개입, 투명성 요구사항이 없어 장애 때 중단할 수 없는 기능이 배포됨
  • 설명 가능성을 평가하면서 화면의 근거 문구 표시 여부만 확인함. 표시된 근거가 실제 근거와 일치하는지는 확인하지 않음
  • 모델 갱신으로 적응한 결과를 확인하지 않고 운영에 반영함
  • 측정 조건(평가셋·모델·프롬프트 버전)을 기록하지 않아 회차 간 결과를 비교할 수 없음

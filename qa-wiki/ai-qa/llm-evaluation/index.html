LLM 평가셋과 LLM 심판

LLM 기능의 회귀를 확인하는 기준 질의 모음(평가셋)과, 자유 서술 응답을 다른 LLM으로 채점하는 방식(LLM 심판)의 구성 원칙이다. 심판 모델도 편향이 있어 사람 판정과 주기적으로 대조한다.

기본기난이도 심화AI 제품최종 업데이트 2026-11-24

평가셋(골든셋, Golden Dataset)은 LLM 기능의 회귀 테스트 스위트다. 프롬프트나 모델을 변경할 때마다 같은 평가셋을 실행해 버전별 결과를 비교한다. 자유 서술 응답은 코드로 채점하기 어려워 다른 LLM에 채점을 맡기는데(LLM-as-a-Judge), 이 심판도 검증 대상이다.

평가셋 구성

섹션 제목: “평가셋 구성”
  • 정상 질의: 실제 사용자가 가장 많이 하는 유형
  • 경계·모호 질의: 조건이 빠졌거나 두 가지로 해석되는 질문
  • 거부해야 하는 질의: 범위 밖 질문, 유해 요청, 권한 밖 정보 요청
  • 거부하면 안 되는 질의: 보안·의학·법률 용어가 들어간 정상 질문. 과차단을 잡기 위한 항목
  • 과거 실패 재현 질의: 결함으로 등록되었던 입력. 결함을 종결할 때 평가셋에 추가함
  • 적대적 입력: 프롬프트 인젝션, 역할극 우회, 인코딩 우회

질의마다 기대 조건(구조 조건, 포함해야 할 사실, 금지 내용)과 유형 라벨을 함께 저장한다. 유형별 통과율을 따로 집계하면 전체 통과율은 같아도 특정 유형(거부 질의 등)의 통과율이 떨어진 변경을 발견할 수 있다.

평가셋 관리

섹션 제목: “평가셋 관리”
  • 버전 관리: 평가셋도 코드처럼 변경 이력을 남김. 평가셋을 수정한 회차와 모델을 변경한 회차를 같은 회차로 섞지 않음
  • 오염 방지: 프롬프트 예시나 미세 조정 데이터에 사용한 문장을 평가셋에 포함하지 않음. 포함하면 외운 답으로 통과함
  • 비교 지표: 유형별 통과율, 거부율, 과차단율, 응답 시간, 토큰 사용량
  • 기준선 고정: 비교 기준이 되는 버전의 결과를 저장해 두고 새 버전과 같은 조건으로 실행함

LLM 심판 설계

섹션 제목: “LLM 심판 설계”
  • 채점 기준은 “1~10점” 같은 총점 대신 통과·실패 이진 판정이나, 단계마다 조건이 정의된 3~5단계 기준으로 작성함
  • 점수만 받지 않고 어느 기준에서 실패했는지 판정 근거 문장을 함께 출력하게 함
  • 스키마, 수치 계산, 날짜, 링크 유효성처럼 코드로 판정할 수 있는 항목은 심판에서 제외하고 코드로 검사함
  • 심판은 생성 모델과 다른 모델을 사용함. 같은 계열 모델은 자기 출력을 후하게 채점하는 경향이 있음

심판의 편향

섹션 제목: “심판의 편향”
편향 증상 통제
위치 편향 두 답 비교 시 특정 위치의 답을 선호 순서를 변경해 두 번 채점하고 일치할 때만 채택
길이 편향 길고 유창한 답에 높은 점수 기준표에 길이와 무관한 판정 조건 명시
자기 선호 같은 계열 모델의 출력을 후하게 채점 생성 모델과 다른 모델로 채점
계산 약점 수치와 코드 결과를 틀리게 판정 해당 항목은 코드로 판정

사람 판정과의 대조

섹션 제목: “사람 판정과의 대조”

LLM 심판만으로 품질을 확정하지 않는다. 표본을 뽑아 사람이 직접 판정하고, 사람 판정과 심판 판정의 일치율을 주기적으로 측정한다. 일치율이 떨어지면 심판의 채점 기준이나 프롬프트를 수정하고, 수정한 심판으로 기준선부터 다시 채점한다.

TC 예시

섹션 제목: “TC 예시”
항목 TC 예시
유형별 회귀 평가셋을 실행해 유형 라벨별 통과율을 기준선 결과와 비교함. 전체 통과율이 같아도 어느 한 유형의 통과율이 허용 폭(예: 5%p)보다 크게 떨어지면 회귀로 판정함
과거 실패 재현 결함 종결 때 추가한 입력을 실행해 그 결함의 실패 조건이 다시 나타나지 않는지 확인함
오염 검사 공백과 문장부호를 정규화한 뒤 평가셋 질의를 프롬프트 예시, 미세 조정 데이터와 비교해 일치하는 질의가 0건인지 확인함. 조사나 어미만 다른 유사 질의는 완전 일치로 걸리지 않아 n-gram 겹침이나 임베딩 유사도 상한으로 함께 확인함
심판 일관성 같은 응답을 같은 심판으로 반복(예: 3회) 채점해 판정이 모두 같은지 확인함. 판정이 갈린 응답의 비율을 기록하고, 갈린 응답은 사람이 판정함
위치 편향 두 답 A, B의 제시 순서를 변경해 두 번 비교 채점함. 두 번의 선택이 다르면 그 비교 결과를 채택하지 않음
길이 편향 만점이 아닌 부분 정답(예: 5점 척도의 3점 답안)에 질문과 무관한 문장을 덧붙여 길이를 늘린 변형(예: 2배)을 채점해 원래 답보다 점수가 오르지 않는지 확인함. 만점 답안으로 확인하면 점수가 더 오를 수 없어 편향이 있어도 통과함
심판 검출력 정답 답변에 수치 오류, 근거 없는 문장, 필수 요소 누락을 하나씩 주입한 변형을 만들어 각 변형이 실패로 판정되는지 확인함
사람 판정 대조 표본(예: 50건)을 사람과 심판이 각각 판정해 일치율을 계산함. 일치율이 기준(예: 90%) 미만이면 심판 결과로 출시를 판정하지 않음
채점 누락 심판 호출 실패, 빈 응답, 형식 오류로 점수가 없는 건수를 집계해 0건인지 확인함. 0건이 아니면 보고서에 미채점으로 표시되는지 확인함

적용 예: 회의록 요약

섹션 제목: “적용 예: 회의록 요약”

기획서에 “회의 녹취록을 받아 결정 사항, 할 일(담당자와 기한), 미결 사항을 요약한다”만 있는 경우, 평가셋과 심판 설계에서 정할 항목은 다음과 같다.

  • 정상 질의: 주간 회의, 장애 회고, 일대일 면담처럼 실제로 많은 회의 유형의 녹취를 포함함
  • 경계·모호 질의: 결정 사항이 없는 회의, 담당자를 정하지 않은 할 일, 화자 이름이 없는 녹취, 한국어와 영어가 섞인 회의를 포함함
  • 거부해야 하는 질의: 녹취에 없는 참석자 평가나 인사 판단을 요청하는 입력을 포함함
  • 과거 실패 재현 질의: 할 일의 담당자를 다른 참석자로 기재했던 녹취처럼 결함으로 등록된 입력을 추가함
  • 기대 조건: 녹취마다 결정 사항 목록, 할 일과 담당자·기한 목록, 금지 내용(녹취에 없는 기한, 언급되지 않은 담당자)을 저장함
  • 코드 판정: 할 일을 구조화된 필드로 출력하게 하고 담당자와 기한을 기대 목록과 대조해 재현율(맞게 추출한 기대 항목 수 / 전체 기대 항목 수)과 정밀도(맞게 추출한 항목 수 / 전체 추출 항목 수)를 계산함
  • 심판 판정: 결정 사항의 의미 일치와 미결 사항 누락을 이진 조건으로 채점하고 조건마다 근거가 된 녹취 문장을 출력하게 함
  • 심판 입력: 녹취 전문과 요약을 함께 제공함. 녹취가 길어 일부만 넣으면 발췌 밖 내용을 사실이 아닌 것으로 판정할 수 있어, 일부만 넣을 때는 그 사실을 심판 프롬프트에 명시하고 발췌 밖 항목은 확인 불가로 분리함
  • 사람 대조: 첫 회차는 전체를 사람이 판정해 심판 일치율을 측정하고, 이후 회차는 표본으로 대조함

담당자와 기한은 코드로, 결정 사항의 의미는 심판으로 판정한다. 하나의 총점으로 묶으면 담당자를 잘못 기재한 요약도 다른 조건의 점수가 높아 기준을 넘을 수 있으므로 조건별 결과를 따로 저장한다.

테스트 계획, 결함 분류, 보고에 적용

섹션 제목: “테스트 계획, 결함 분류, 보고에 적용”

테스트 계획

  • 출시 조건을 유형별로 정함. 예: 거부해야 하는 질의 100% 통과, 정상 질의 95% 이상, 기준선 대비 하락한 유형 없음
  • 심판 검증(사람 대조, 결함 주입 변형, 반복 채점 일관성)을 평가셋 본 실행보다 앞선 일정에 둠
  • 평가셋 실행 비용(호출 수, 토큰)과 한도 초과 시 재개 절차를 계획에 포함함

결함 분류

  • 평가셋 실패를 결함으로 등록하기 전에 원인을 생성 결함, 심판 오판, 평가셋 오류(기대 조건이 틀림)로 구분함. 심판 오판과 평가셋 오류는 제품 결함 수에 넣지 않고 평가 도구의 결함으로 따로 기록함
  • 결함을 종결할 때 재현 입력을 평가셋에 추가하고, 이슈에 평가셋 항목 식별자를 남김

보고

  • 유형별 통과율과 기준선 대비 변화, 심판과 사람 판정의 일치율, 미채점 건수를 함께 보고함. 예: “정상 188/200(기준선 190), 거부 40/40, 과차단 2/40, 심판-사람 일치 46/50, 미채점 0”
  • 심판 판정만 있는 결과와 사람이 확인한 결과를 구분해 표기함

현장 노트

  • 생성 모델과 다른 계열의 모델을 심판으로 두고 표와 재무 수치가 많은 리서치 PDF 요약을 원문 발췌와 대조해 채점함. 같은 요약과 같은 심판 프롬프트로 다시 채점하자 27점(심각 오류 2건)과 94점(심각 오류 0건)이 나옴. 이후 심각 오류 판정은 1회로 확정하지 않고 재실행과 원문 대조로 확인하며, 개별 점수는 품질 지표로 사용하지 않음. 평균 추세도 같은 평가셋, 같은 채점 기준, 같은 반복 횟수로 채점한 회차끼리만 비교함
  • 심판 입력은 원문 앞부분 발췌였고, 발췌 밖 내용을 쓴 요약을 원문에 없는 내용으로 판정하는 오탐이 반복됨. 원문 전문과 대조한 결과 177건 회차는 심각 오류 판정 52건 중 49건, 321건 회차는 31건 중 30건이 오탐이었고, 대부분 이 유형이었음. 판정 근거에 쪽수를 언급한 280건 중 274건은 실제 쪽수와 3쪽 이상 차이가 있었음. 심판 프롬프트에 총 쪽수와 “본문은 부분 발췌”라는 안내를 추가하고, 발췌 밖 항목은 [확인불가]로 분리해 재검증 대상으로 집계함
  • 심판이 요약에 없는 서술을 근거로 오류를 지적한 사례가 있었음. 이후 지적을 확인할 때 원문 대조보다 먼저 그 서술이 요약에 실제로 있는지 확인함. 십억원 단위 표를 억원으로 잘못 환산해 본문의 정밀값과 모순이라고 판정한 오탐도 반복됨
  • 사용량 한도로 받은 빈 응답이 채점 실패 결과로 캐시되었고, 다음 실행이 이를 완료분으로 건너뛰어 미검증 건이 검증 완료처럼 집계됨. 집계에서 점수가 없는 건수를 따로 셈
  • 차트 수치 귀속 오류 등을 전수 점검해 찾은 오류 12건 중 심판이 검출한 건은 0건이었음. 심판 입력(원문 발췌)에 해당 정보가 없었던 것으로 판단함. 이 유형은 요약 작성 단계의 검사로 관리함(LLM 기능 테스트)

규칙

  • 평가셋 결과를 비교할 때는 평가셋 버전, 심판 모델과 버전, 채점 기준 버전을 함께 기록함
  • 심판의 채점 기준을 변경하면 이전 회차 점수와 직접 비교하지 않음

  • 전체 평균 점수만 확인하고 유형별 퇴보를 놓침

관련 문서

AI와 QALLM 기능 테스트같은 입력에도 출력이 달라지는 LLM 기능을 구조 조건, 의미 평가, 반복 실행 통과율로 판정하는 테스트 방법이다. 정확한 문자열 대신 성립해야 하는 조건을 기대 결과로 쓴다.AI와 QARAG 테스트검색 증강 생성(RAG) 기능을 검색 단계와 생성 단계로 나눠 각각 검증하는 방법이다. 최종 답만 확인하면 오답의 원인이 검색인지 생성인지 구분할 수 없다.프로세스회귀 테스트 범위 선정변경 뒤 기존 기능이 의도하지 않게 실패하는지 확인하기 위해, 회귀 스위트에서 이번 회차에 수행할 TC를 선택하는 절차다(Regression Test Selection).

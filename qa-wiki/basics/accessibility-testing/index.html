접근성 테스트 기본

장애가 있는 사용자와 보조 기술(스크린 리더, 키보드) 사용자도 화면을 인식하고 조작할 수 있는지 W3C WCAG 2.2 성공 기준으로 확인하는 테스트다.

기본기난이도 기초웹 프론트엔드최종 업데이트 2026-11-24

WCAG 2.2(Web Content Accessibility Guidelines)는 성공 기준을 A, AA, AAA 세 수준으로 나눈다. 아래 기준은 A와 AA 범위다. 자동 검사로 판정할 수 있는 기준과 사람이 조작해야 판정할 수 있는 기준이 섞여 있어 두 방식을 함께 사용한다.

네 가지 원칙(POUR)

섹션 제목: “네 가지 원칙(POUR)”
  • 인식의 용이성(Perceivable): 대체 텍스트, 대비, 색 외의 단서
  • 운용의 용이성(Operable): 키보드 조작, 포커스, 타깃 크기, 드래그 대안
  • 이해의 용이성(Understandable): 일관된 동작, 오류 식별과 입력 안내
  • 견고성(Robust): 보조 기술이 이름·역할·값을 읽을 수 있는 마크업

점검 항목

섹션 제목: “점검 항목”

대비와 색

  • 1.4.3 텍스트 대비 4.5:1 이상, 큰 텍스트는 3:1 이상
  • 1.4.11 비텍스트 대비: 구성 요소와 상태를 알아보는 데 필요한 시각 정보(입력란 경계, 의미 있는 아이콘, 포커스 표시)와 의미 있는 그래픽은 인접 색과 3:1 이상. 비활성 요소와 작성자가 꾸미지 않은 브라우저 기본 표현은 예외
  • 1.4.1 색만으로 정보를 전달하지 않음. 오류 입력란은 빨간 테두리와 함께 문구나 아이콘으로 표시함
  • 반투명 색(알파 값이 있는 색)은 실제 배경과 합성한 색으로 대비를 계산함. 원래 색 값으로 계산하면 화면과 다른 대비가 나옴
  • 라이트와 다크 테마를 각각 측정함

키보드와 포커스

  • 2.1.1 모든 기능을 키보드만으로 조작할 수 있음
  • 2.1.2 키보드 트랩 없음. 키보드만으로 포커스를 모달이나 위젯 밖으로 이동시킬 수 있음
  • 2.4.3 포커스 순서가 화면의 의미 순서와 일치하고, 2.4.7 포커스 위치가 화면에 표시됨
  • 모달을 열면 포커스가 모달 안으로 이동하고, 닫으면 모달을 연 요소로 돌아옴

이름, 역할, 상태

  • 4.1.2 아이콘만 있는 버튼과 사용자 정의 위젯에 접근 가능한 이름과 역할이 있음. TC 기대 결과는 속성 값이 아니라 스크린 리더가 읽는 문구와 역할로 작성함
  • 1.3.1 입력란과 label 연결, 제목과 목록 같은 구조를 마크업으로 표현함
  • 3.3.1 오류가 발생한 입력란과 오류 내용을 텍스트로 식별함
  • 4.1.3 저장 완료, 검색 결과 개수 같은 상태 메시지를 포커스 이동 없이 보조 기술에 전달함

확대와 재배치

  • 1.4.4 텍스트 200% 확대에서 내용과 기능이 잘리지 않음
  • 1.4.10 리플로: 세로로 스크롤하는 콘텐츠는 320 CSS px 폭에서 가로 스크롤 없이 표시됨. 표, 지도, 도표처럼 2차원 배치가 필요한 콘텐츠는 예외

WCAG 2.2에서 변경된 기준

섹션 제목: “WCAG 2.2에서 변경된 기준”
  • 2.4.11 포커스 가려짐 방지(최소, AA): 고정 헤더나 하단 배너가 포커스를 받은 요소를 완전히 가리지 않음
  • 2.5.7 드래그 동작(AA): 드래그로 하는 조작에 클릭·탭 같은 단일 포인터 대안을 제공함
  • 2.5.8 타깃 크기(최소, AA): 24x24 CSS px 이상. 미달이면 간격 등 예외 조건 충족 여부를 확인함
  • 3.3.8 접근 가능한 인증(최소, AA): 비밀번호 기억이나 문자 옮겨 적기 같은 인지 기능 테스트를 대안 없이 요구하지 않음. 붙여넣기와 비밀번호 관리자를 허용함
  • 3.2.6 일관된 도움말(A), 3.3.7 중복 입력(A): 도움말 수단을 페이지마다 같은 상대 순서에 배치하고, 같은 과정에서 이미 입력한 정보는 자동으로 채우거나 선택할 수 있게 제공함
  • 4.1.1 구문 분석은 2.2에서 삭제됨. 이전 판 기준 점검표에 남아 있으면 제외함

자동 검사와 수동 점검

섹션 제목: “자동 검사와 수동 점검”
  • 자동 검사(axe-core 등): 대비, label 누락, 이름 없는 버튼, ARIA 속성 오류처럼 마크업과 계산으로 판정할 수 있는 항목. 화면과 테마마다 실행해 회귀를 방지함
  • 자동 검사가 판정하지 못하는 항목: 포커스 순서가 의미에 맞는지, 대체 텍스트가 내용을 설명하는지, 모달을 닫은 뒤 포커스 위치, 동적 알림의 전달 여부
  • 키보드 점검: 마우스 없이 Tab, Shift+Tab, Enter, Space, 방향키, Esc로 주요 흐름을 수행함
  • 스크린 리더 점검: NVDA(Windows), VoiceOver(macOS, iOS) 등으로 주요 흐름을 수행하고 읽히는 이름·역할·상태를 확인함

TC 예시

섹션 제목: “TC 예시”
기준 TC 예시
1.4.3 텍스트 대비 라이트·다크 테마에서 버튼 라벨과 배경색의 대비를 측정해 4.5:1 이상인지 확인함
1.4.11 비텍스트 대비 입력란 테두리와 포커스 표시를 인접 배경과 비교해 3:1 이상인지 확인함
2.1.1 키보드 마우스 없이 Tab, Enter, Space만으로 회원 가입을 끝까지 완료할 수 있는지 확인함
2.4.11 포커스 가려짐 방지 고정 헤더가 있는 긴 목록에서 Tab으로 이동할 때 포커스된 항목이 헤더에 완전히 가려지지 않는지 확인함
3.3.1 오류 식별 필수 입력란을 비우고 제출했을 때 오류 문구가 해당 입력란과 연결되어 스크린 리더가 읽는지 확인함
3.3.8 접근 가능한 인증 로그인 화면의 비밀번호 입력란에서 붙여넣기와 비밀번호 관리자 자동 입력이 동작하는지 확인함
4.1.2 이름, 역할, 값 아이콘만 있는 닫기 버튼을 스크린 리더로 탐색했을 때 “닫기, 버튼”처럼 이름과 역할이 읽히는지 확인함

적용 예: 로그인 화면

섹션 제목: “적용 예: 로그인 화면”

로그인 화면 하나를 WCAG 2.2 AA 기준으로 점검하면 다음 항목이 나온다.

  • 아이디·비밀번호 입력란과 화면에 표시된 label의 연결 여부(1.3.1, 4.1.2)
  • 비밀번호 표시 버튼(눈 아이콘)의 접근 가능한 이름과 눌림 상태(4.1.2)
  • 로그인 실패 문구의 스크린 리더 전달 여부(포커스 이동 없이, 4.1.3)
  • 붙여넣기 허용, 자동 입력 허용, 문자 퍼즐형 캡차의 대안 제공 여부(3.3.8)
  • 비밀번호 찾기 링크와 로그인 버튼의 타깃 크기 24x24 CSS px 이상 여부(2.5.8)
  • 200% 확대와 320 CSS px 폭에서 입력란과 버튼의 잘림 여부(1.4.4, 1.4.10)

테스트 계획, 결함 분류, 보고에 적용

섹션 제목: “테스트 계획, 결함 분류, 보고에 적용”
  • 디자인 리뷰: 구현 전 시안 단계에서 색상 토큰의 대비(1.4.3, 1.4.11), 타깃 크기(2.5.8), 아이콘 버튼의 이름(4.1.2), 모달을 닫은 뒤 포커스가 돌아갈 위치를 먼저 정함
  • 계획: 자동 검사(axe-core 등)는 화면과 테마마다 E2E에 넣어 빌드마다 실행함. 릴리즈마다 수행하는 주요 흐름의 키보드·스크린 리더 점검은 회귀 점검이며, AA 적합성을 보고하려면 대상 페이지 전체와 연결된 절차 전체를 평가함
  • 결함 분류: 결함마다 WCAG 성공 기준 번호와 수준(A, AA)을 기록함. 같은 기준의 결함을 모으면 디자인 시스템 컴포넌트 하나를 고쳐 여러 화면을 함께 해결할 수 있음
  • 보고: “접근성 통과” 대신 화면별로 자동 검사 결과, 수동 점검한 기준, 점검하지 않은 기준을 구분해 보고함. 예: “12개 화면 자동 검사 위반 0건 / 로그인·결제 흐름 키보드(2.1.1, 2.4.7)와 스크린 리더(4.1.2, 4.1.3) 수동 점검 통과 / 320 CSS px 리플로(1.4.10) 미검증”

현장 노트

  • 디자인 시스템의 라이트 테마 강조색이 흰 버튼 라벨 대비 4.23으로 AA 기준(4.5) 미달이었음. 같은 계열의 더 진한 색(amber-700)으로 변경함. 다크 테마의 보조 글자색도 가장 밝은 표면 위에서 AA를 넘도록 밝기를 조정함
  • 윈도우 고대비(강제 색상) 모드에서 위키의 규칙·현장 노트 아이콘이 표시되지 않음. 아이콘에 시스템 글자색이 적용되도록 수정하고, 강제 색상 모드를 켠 E2E 테스트를 추가함
  • 위키 전체 문서에 axe 검사를 라이트·다크 테마와 1440·1024·390px 폭별 E2E로 돌려 위반 0건을 빌드마다 확인함
  • 넓은 화면(1440px)과 wcag2a, wcag2aa 태그만으로 검사하면 좁은 화면에서만 나타나는 결함(모바일 목차의 현재 절 이름 대비 1.03:1, 넘치는 표에 키보드 초점이 가지 않음)과 WCAG 2.1·2.2에서 추가된 기준이 검사 범위에서 빠짐
  • 검사 대상에 좁은 화면(1024·390px)을 추가하자 두 결함이 검출됨. wcag21a, wcag21aa, wcag22aa를 추가하자 Starlight 검색 버튼의 접근 이름 불일치(2.5.3) 1건이 새로 검출됨. 외부 컴포넌트라 규칙과 대상을 함께 좁혀 제외하고 근거를 테스트 코드에 기록함

규칙

  • 자동 검사 결과 0건만으로 접근성 PASS를 판정하지 않음. 키보드 점검을 함께 수행함
  • 대비는 렌더링된 최종 색으로 측정함

흔한 실수

섹션 제목: “흔한 실수”
  • outline: none으로 포커스 표시를 제거하고 대체 표시를 제공하지 않음
  • 클릭 이벤트만 연결한 div 버튼. 마우스로는 동작하지만 키보드 포커스를 받지 못함
  • 모달을 열어도 포커스가 뒤 화면에 남아 Tab 이동이 모달 밖으로 빠져나감
  • 포커스를 받은 입력란이 고정 헤더에 가려져 화면에 표시되지 않음(2.4.11)
  • 반투명 색의 원래 값으로 대비를 계산해 미달을 통과로 판정함

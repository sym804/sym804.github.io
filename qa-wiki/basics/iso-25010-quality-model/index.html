ISO/IEC 25010 품질 모델

ISO/IEC 25010:2023은 ICT 제품과 소프트웨어 제품의 품질을 특성 9개와 그 부특성으로 나눈 참조 모델이다. 요구사항 리뷰, 테스트 계획, 결함 분류, 품질 보고에서 빠진 품질 영역을 찾는 기준으로 사용한다.

기본기난이도 중급최종 업데이트 2026-11-24

ISO/IEC 25010은 SQuaRE(Systems and software Quality Requirements and Evaluation, ISO/IEC 25000~25099) 시리즈의 품질 모델이다. 기능 테스트만 하면 “기능이 명세대로 동작하는가”만 확인하게 된다. 25010은 성능, 호환성, 신뢰성, 보안성처럼 기능 테스트에서 빠지기 쉬운 영역까지 9개 특성으로 나눠, 요구사항과 테스트 범위에서 무엇이 빠졌는지 확인할 수 있게 한다.

특성 9개와 부특성

섹션 제목: “특성 9개와 부특성”
  • 기능 적합성(Functional Suitability): 기능 완전성, 기능 정확성, 기능 적절성
  • 성능 효율성(Performance Efficiency): 시간 반응성, 자원 활용성, 용량
  • 호환성(Compatibility): 공존성, 상호운용성
  • 상호작용 능력(Interaction Capability): 적절성 인지성, 학습성, 운용성, 사용자 오류 보호, 사용자 참여, 포용성, 사용자 지원, 자기 서술성
  • 신뢰성(Reliability): 무결함성, 가용성, 결함 허용성, 복구성
  • 보안성(Security): 기밀성, 무결성, 부인 방지, 책임 추적성, 인증성, 저항성
  • 유지보수성(Maintainability): 모듈성, 재사용성, 분석성, 수정 용이성, 시험성
  • 유연성(Flexibility): 적응성, 확장성, 설치성, 대체성
  • 안전성(Safety): 운영 제약, 위험 식별, 페일 세이프, 위해 경고, 안전한 통합

한국어 명칭은 이 위키의 번역이다. 문서나 보고서에서 표준을 인용할 때는 영문 원어를 함께 적는다. 2011판과 달라진 점은 아래 「판 확인」 절에 있다.

특성별 점검 항목과 TC 예시

섹션 제목: “특성별 점검 항목과 TC 예시”

관련 위키 문서: 기능 적합성은 경계값 분석과 결정 테이블 테스트, 상호작용 능력은 접근성 테스트 기본, 보안성은 보안 테스트의 기본 관점, 유연성은 조합 테스트(페어와이즈).

적용 예: CSV 내보내기 기능의 요구사항 리뷰

섹션 제목: “적용 예: CSV 내보내기 기능의 요구사항 리뷰”

기획서에 “목록 화면에 CSV 내보내기 버튼을 추가한다. 현재 필터가 적용된 목록을 내려받는다.“만 있는 경우, 9개 특성을 대응시키면 기획과 확인할 항목은 다음과 같다.

  • 기능 적합성: 숫자·날짜 서식, 쉼표와 줄바꿈이 든 값의 처리 방식, 필터가 없을 때의 내보내기 범위
  • 성능 효율성: 최대 행 수, 10만 행일 때의 응답 시간과 서버 메모리 상한, 생성 중 다른 요청의 지연 허용치
  • 호환성: 대상 엑셀 환경에서 파일을 바로 열 때와 가져오기로 열 때의 한글 표시(UTF-8 BOM 포함 여부와 그 영향), 이 파일을 읽는 다른 시스템의 열 구성 변경 대응
  • 상호작용 능력: 생성 중 진행 표시, 0건일 때 안내 문구, 키보드로 버튼에 접근할 수 있는지 여부
  • 신뢰성: 생성 중 네트워크가 끊겼을 때 다시 내려받을 수 있는지 여부
  • 보안성: 다른 조직 데이터의 혼입 차단, 권한 없는 역할의 버튼 노출과 API 직접 호출 차단, 셀 값이 =, +, -, @, 탭으로 시작할 때 수식으로 실행되지 않도록 처리하는지 여부(CSV 인젝션)
  • 유지보수성: 내보내기 실패 원인의 로그 기록 여부
  • 유연성: 데이터가 늘어날 때 동기 응답을 비동기 생성으로 전환하는 기준
  • 안전성: 해당 없음(제외 사유를 기록)

보안성의 CSV 인젝션과 데이터 격리, 호환성의 인코딩은 기능 테스트 관점만으로는 도출되지 않는 항목이다. 확인한 항목을 요구사항에 반영한 뒤 항목마다 기대 결과와 테스트 범위를 정한다.

테스트 계획, 결함 분류, 보고에 적용

섹션 제목: “테스트 계획, 결함 분류, 보고에 적용”

테스트 계획

  • 특성마다 이번 릴리즈의 영향과 발생 가능성을 평가해 테스트할 특성을 선정함(리스크 기반 테스트)
  • 제외한 특성과 사유를 계획서에 기록함. 예: 안전성 “사람·재산에 영향을 주는 기능 없음”, 유연성 “지원 환경, 설치 절차, 확장 요구사항에 변경과 영향 없음”
  • 측정 목표는 판정할 수 있는 수치로 작성함. “빨라야 한다”가 아니라 “동시 사용자 50명 조건에서 검색 응답 시간 95백분위수(p95) 2초 이하”

결함 분류

  • 이슈 양식에 품질 특성 칸이나 라벨을 추가해 결함마다 특성을 하나 지정함
  • 릴리즈 단위로 특성별 결함 수를 집계하면 기능 테스트만으로 확인되지 않는 영역이 드러남. 예: 성능, 호환성 결함이 운영에서 주로 발견되면 해당 특성의 테스트 범위, 환경, 데이터, 판정 기준을 재검토함

품질 보고

  • 릴리즈 품질 보고를 특성 단위로 작성함. “테스트 300건 중 295건 통과”보다 “보안성 중 접근 제어: 계획한 권한 TC 40건 통과, 세션과 입력 처리는 별도 기록 / 성능: 목표 미측정”처럼 확인한 범위와 미검증 범위를 구분해 기록함
  • 측정 방법은 ISO/IEC 25023:2016(제품 품질 측정)을, 평가 절차는 ISO/IEC 25040:2024(품질 평가 프레임워크)를 참고함. 25023:2016은 25010:2011 기준이라 2023판에서 추가된 특성(안전성 등)의 측정 방법은 포함하지 않음. 25040은 평가 틀을 정하며 구체적인 테스트 방법은 제공하지 않음

현장 노트

  • 성능 효율성(자원 활용성): 실시간 API에서 PDF 파싱을 수행해 CPU 온도가 80도까지 올라감. 연산 부하가 큰 작업을 배치로 분리하고, 서버 실행·대량 작업 시 CPU 사용률과 온도를 확인하는 규칙을 추가함
  • 성능 효율성(시간 반응성): 서버리스 배포에서 유휴 뒤 첫 요청이 느림. 원인은 무료 플랜의 인스턴스 0개 축소였고, 첫 요청 처리 코드를 줄인 뒤 40분 유휴 후 첫 요청이 3.69초에서 3.13초로 관측됨(각 1회 측정). 남은 지연은 플랜 문제로 기록함
  • 보안성(저항성): 요청 횟수 제한이 클라이언트가 보낸 X-Forwarded-For 헤더의 IP를 기준으로 동작해 헤더 조작으로 우회됨. IP 대신 서버 전체 합계 기준으로 변경함
  • 상호작용 능력(포용성): 윈도우 고대비(강제 색상) 모드에서 위키의 규칙·현장 노트 아이콘이 표시되지 않음. 아이콘에 시스템 글자색(CanvasText)이 적용되도록 수정하고 E2E 테스트를 추가함
  • 유연성(설치성): CI 러너의 기본 OS가 새 버전으로 바뀌면서 Playwright 브라우저 설치가 실패함. 러너 OS 버전을 고정함
  • 기능 적합성(기능 정확성): 백테스트의 재무 데이터 조인을 공시일 기준으로 변경하자 CAGR이 39%에서 3.9%로 변경됨(금융 데이터 검증의 함정)

규칙

  • 9개 특성을 모두 같은 깊이로 테스트하지 않음. 제품 특성과 리스크로 범위를 정하고, 제외한 특성과 그 근거를 테스트 계획에 기록함
  • 비기능 요구사항은 측정 조건과 목표값이 있는 문장으로 받음. 목표값이 없으면 기획과 확인 항목으로 기록함

판 확인

섹션 제목: “판 확인”
  • 안전성(Safety)이 특성으로 추가됨. 부특성은 운영 제약(Operational constraint), 위험 식별(Risk identification), 페일 세이프(Fail safe), 위해 경고(Hazard warning), 안전한 통합(Safe integration)
  • 사용성(Usability)은 상호작용 능력(Interaction Capability)으로, 이식성(Portability)은 유연성(Flexibility)으로 대체됨
  • 상호작용 능력에 포용성과 자기 서술성, 보안성에 저항성, 유연성에 확장성이 부특성으로 추가됨
  • 사용자 인터페이스 심미성은 사용자 참여로, 성숙성은 무결함성으로 대체됨. 접근성은 포용성과 사용자 지원으로 나뉨
  • 2011판에 함께 있던 사용 품질 모델은 ISO/IEC 25019:2023으로, 품질 모델 개요와 사용법은 ISO/IEC 25002(25010:2023과 함께 제정된 1판)로 분리됨
  • 25019:2023 사용 품질 모델은 정해진 사용 맥락에서 이해관계자에게 미치는 영향을 이로움(Beneficialness), 위험으로부터의 자유(Freedom from risk), 수용성(Acceptability) 세 특성으로 다룸. 기능과 응답 시간이 25010 기준을 통과해도 사용자가 업무 목표를 달성하지 못하면 사용 품질 문제이며, 인수 테스트와 베타 테스트의 시나리오 기준으로 사용함

흔한 실수

섹션 제목: “흔한 실수”
  • 2011판의 사용성, 이식성 같은 이름을 2023판 기준이라고 인용함
  • 특성 목록을 체크리스트로만 사용하고, 특성마다 측정 기준과 목표값을 정하지 않음. “성능 확인”은 판정할 수 있는 기대 결과가 아님
  • 비기능 특성을 시스템 테스트 마지막에 몰아서 확인함. 성능과 유지보수성은 하위 레벨부터 측정할 수 있음
  • 통과율 하나로 품질을 보고함. 어떤 특성을 확인하지 않았는지가 보고서에 남지 않음

관련 문서

기초와 용어품질 표준 지도소프트웨어 품질과 테스트에 관련된 국제 표준과 업계 기준을 다루는 대상별로 묶고, 무엇을 확인할 때 어떤 표준을 참고하는지와 관련 위키 문서를 연결한다.테스트 설계리스크 기반 테스트실패했을 때의 피해와 실패할 가능성을 기준으로 무엇을 먼저, 얼마나 깊게 테스트할지 정하는 방식이다(Risk-Based Testing).AI와 QAAI 시스템 품질 모델(ISO/IEC 25059)ISO/IEC 25059:2023은 25010 품질 모델에 AI 시스템 고유의 부특성을 추가하거나 수정한 확장 모델이다. AI 기능의 품질 요구사항과 테스트 범위에서 빠진 항목을 확인하는 기준으로 사용한다.

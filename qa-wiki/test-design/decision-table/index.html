결정 테이블 테스트

여러 조건의 조합에 따라 동작이 달라지는 규칙을 표로 정리하고, 표의 열마다 테스트 케이스를 도출하는 기법이다(Decision Table Testing). 명세의 누락과 모순을 설계 단계에서 찾는 데도 사용한다.

기본기난이도 기초최종 업데이트 2026-11-24

동등 분할은 입력 하나를 묶음으로 나누고, 결정 테이블은 조건 여럿이 함께 결과를 정하는 규칙을 다룬다. 할인, 권한, 요금, 승인처럼 “A이고 B이면 C” 형태의 업무 규칙이 대상이다.

표의 구성

섹션 제목: “표의 구성”
  • 조건(Condition) 행: 결과에 영향을 주는 입력 조건. 값은 예/아니요 또는 이산 값
  • 동작(Action) 행: 조건 조합에 따라 수행되는 동작이나 출력
  • 열(규칙, Rule): 조건 값 조합 하나와 그때 수행되는 동작

절차

섹션 제목: “절차”
  1. 명세에서 조건과 동작을 분리함
  2. 수치 범위 조건은 동등 분할로 먼저 묶어 이산 값으로 변환함
  3. 완전 테이블을 작성함. 예/아니요 조건이 n개면 2ⁿ열, 이산 값이면 각 조건 값 개수의 곱
  4. 열마다 동작을 기록함. 동작을 정할 수 없는 열은 명세 확인 항목으로 기록함
  5. 축소: 불가능한 조합의 열을 제거하고, 한 조건의 값과 무관하게 동작이 같은 열은 무관 기호(-)로 병합함
  6. 남은 열마다 TC를 하나 이상 작성함

열 커버리지는 수행한 열 수를 축소 후 남은 실행 가능한 열 수로 나눈 값이다. 무관 기호 자리도 TC를 수행할 때는 실제 값이 필요하므로, TC에 선택한 값을 명시한다.

예: 쿠폰과 무료 배송

섹션 제목: “예: 쿠폰과 무료 배송”

가상의 명세: 쿠폰은 주문 금액이 기준 이상일 때만 적용된다. VIP 회원은 항상 무료 배송이고, 일반 회원은 주문 금액이 기준 이상일 때 무료 배송이다.

조건 셋(VIP 회원, 기준 금액 이상, 쿠폰 보유)의 완전 테이블은 8열이다. 축소하면 아래 4열이 남는다.

규칙 1 규칙 2 규칙 3 규칙 4
조건: VIP 회원 - - 예 아니요
조건: 기준 금액 이상 예 예 아니요 아니요
조건: 쿠폰 보유 예 아니요 - -
동작: 쿠폰 할인 적용 미적용 미적용 미적용
동작: 무료 배송 적용 적용 적용 미적용
  • 규칙 1, 2: 기준 금액 이상이면 회원 등급과 무관하게 무료 배송이라 VIP 조건을 병합함
  • 규칙 3, 4: 기준 금액 미만이면 쿠폰 보유와 무관하게 쿠폰이 미적용되어 쿠폰 조건을 병합함
  • 표를 채우는 동안 명세로 답할 수 없는 질문이 발견됨. 예: 쿠폰 할인 뒤 금액이 기준 아래로 내려가면 무료 배송을 유지하는지. 이런 질문은 확인 항목으로 기록함

TC 예시

섹션 제목: “TC 예시”

위 표의 규칙에서 도출한 TC다. 기준 금액은 예로 50,000원을 사용한다. “기준 금액 이상” 조건의 값으로 경계값 분석의 경계값(50,000원, 49,999원)을 선택하면 비교 연산자 결함도 같은 TC에서 확인된다.

규칙 TC 예시
규칙 1 일반 회원(무관 자리에 선택한 값), 주문 금액 50,000원, 쿠폰 보유 상태로 결제 화면에 진입해 쿠폰 할인이 적용되고 배송비가 0원으로 표시되는지 확인함
규칙 2 VIP 회원(무관 자리에 선택한 값), 주문 금액 50,000원, 쿠폰 없음 상태에서 할인 없이 배송비가 0원으로 표시되는지 확인함
규칙 3 VIP 회원, 주문 금액 49,999원, 쿠폰 보유 상태에서 쿠폰을 선택하면 명세의 사용 조건 미충족 문구가 표시되고 배송비가 0원으로 표시되는지 확인함
규칙 4 일반 회원, 주문 금액 49,999원, 쿠폰 보유 상태에서 쿠폰이 적용되지 않고 명세의 배송비가 부과되는지 확인함
무관 자리 확인 규칙 1을 VIP 회원으로 다시 수행해 결과가 같은지 확인함. 결과가 다르면 병합이 구현과 맞지 않는다는 뜻임

적용 예: 게시글 수정·삭제 권한

섹션 제목: “적용 예: 게시글 수정·삭제 권한”

요구사항이 “작성자는 자기 글을 수정·삭제할 수 있다. 관리자는 모든 글을 삭제할 수 있다. 답변이 달린 글은 수정할 수 없다.” 세 문장인 경우, 조건은 작성자 본인 여부, 관리자 여부, 답변 유무 셋이고 동작은 수정 허용과 삭제 허용 둘이다.

완전 테이블은 2³ = 8열이다. 명세 문장으로 각 열의 동작을 채운 뒤 축소하면 아래 5열이 남는다.

규칙 1 규칙 2 규칙 3 규칙 4 규칙 5
조건: 작성자 본인 예 예 - 아니요 아니요
조건: 관리자 - 아니요 예 예 아니요
조건: 답변 있음 아니요 예 예 아니요 -
동작: 수정 허용 거부 거부 명세 없음 거부
동작: 삭제 허용 허용 허용 허용 거부
  • 규칙 1: 본인 글이고 답변이 없으면 관리자 여부와 무관하게 수정·삭제가 허용되어 관리자 조건을 병합함
  • 규칙 3: 관리자가 답변이 달린 글을 처리하는 경우 본인 글인지와 무관하게 수정 거부, 삭제 허용이라 본인 조건을 병합함
  • 규칙 5: 본인도 관리자도 아니면 답변 유무와 무관하게 모두 거부되어 답변 조건을 병합함

명세 없음 칸은 규칙 4의 수정 하나다. 관리자에게는 삭제 권한만 적혀 있어 다른 사람의 글을 수정할 수 있는지가 정해지지 않았으므로 기획과 확인한다. 규칙 2의 삭제는 첫 문장대로 허용이다. 답변이 달린 글의 삭제도 막을 의도였다면 명세에 추가해야 하므로 함께 확인한다.

확인 항목을 확정한 뒤 규칙마다 TC를 작성한다. 거부 동작은 수정·삭제 버튼이 표시되지 않는지 확인하고, 같은 요청을 API로 직접 전송해 403이 반환되며 게시글이 변경되지 않는지도 확인한다(보안 테스트의 기본 관점). “답변 있음”은 답변 수가 0건에서 1건이 되는 경계이고, 답변이 삭제되어 다시 0건이 되었을 때 수정이 다시 허용되는지는 상태 전이 테스트로 확인한다.

명세 누락과 모순

섹션 제목: “명세 누락과 모순”
  • 누락: 어떤 동작도 정해지지 않은 열. 구현은 그 조합에서도 어떤 동작이든 수행하므로, 그 동작을 검증할 기준이 없어 결함을 놓치기 쉬움
  • 모순: 명세의 두 문장이 같은 열에 서로 다른 동작을 지정한 경우
  • 불가능한 조합: 시스템이 그 조합을 만들 수 없음이 명세나 제약으로 확인된 경우에만 제거함

규칙

  • 동작이 정해지지 않은 열은 TC를 임의로 작성하지 않고 확인 항목으로 기록함
  • 무관 기호 병합은 그 조건이 동작에 영향을 주지 않음을 명세로 확인한 경우에만 적용함

테스트 계획, 결함 분류, 보고에 적용

섹션 제목: “테스트 계획, 결함 분류, 보고에 적용”

테스트 계획

  • 업무 규칙마다 결정 테이블을 TC 설계 산출물로 남기고, 명세 없음 칸은 확인 항목 목록으로 기획 리뷰에 전달함
  • 무관 기호로 병합한 열은 병합 근거가 된 명세 문장을 표 아래에 기록함
  • 열 커버리지 목표를 정함. 예: 권한, 요금 규칙은 축소 후 실행 가능한 열 100%

결함 분류

  • 결함에 규칙(열) 번호와 조건 값 조합을 함께 기록함
  • 무관 자리에 다른 값을 넣어도 재현되는지 기록함. 한 값에서만 재현되면 먼저 명세로 병합 근거를 다시 확인함. 근거가 맞으면 구현 결함으로 기록하고 그 값을 보강 TC로 추가하며, 근거가 틀렸으면 병합한 열을 다시 나눔
  • 명세 없음 칸에서 발견한 동작은 결함으로 바로 등록하지 않고 명세 확인 항목으로 분류함. 기대 동작이 확정된 뒤 결함 여부를 판정함

보고

  • 열 커버리지와 확인 대기 열을 함께 보고함. 예: “게시글 권한 규칙 5열 중 4열 수행, 1열(규칙 4)은 명세 확인 대기”

현장 노트

  • TC 가져오기 기능이 파일 선택기와 서버에서 .xls를 받았지만, 실제 Excel 97-2003 형식 파일은 읽지 못하고 일반 오류(“Failed to read Excel file”)만 반환함. 읽기 라이브러리가 OOXML(zip) 형식만 지원했고, 암호가 걸린 .xlsx도 OLE2 형식이라 같은 오류가 발생함
  • 확장자만으로 차단하면 이름만 .xls인 xlsx 파일이 거부되는 회귀가 발생하므로, 파일 이름의 확장자와 내용의 첫 8바이트(OLE2 서명 여부)를 조건으로 나눠 판정함. OLE2 서명이면 형식 안내 문구와 함께 400을 반환하도록 수정함
  • 조건 조합마다 테스트를 추가함(97-2003 형식 거부, 이름만 .xls인 xlsx 읽기, 이름이 .xlsx인 OLE2 파일 거부, 대문자 확장자 TC.XLSX 허용, 그 외 확장자 거부의 5건)

흔한 실수

섹션 제목: “흔한 실수”
  • 명세를 확인하지 않고 무관 기호로 병합함. 병합된 조합에서만 발생하는 결함이 누락됨
  • 금액, 나이 같은 범위 조건을 원시 값 그대로 조건 행에 배치해 열 수가 불필요하게 늘어남
  • 동작 행에 “정상 처리”처럼 판정 기준이 없는 문구를 기록함. 그대로 기대 결과로 사용할 수 없음
  • 거부 동작을 화면 버튼 숨김으로만 확인함. 권한 규칙의 거부 열은 API로 같은 요청을 보내 확인함
  • 조건 값을 파일 이름, 화면 표시 값처럼 사용자가 변경할 수 있는 정보에서만 가져옴. 판정에 실제로 사용하는 값(파일 내용, 서버의 권한 정보)을 조건으로 둠
  • 조건이 많아 열이 관리하기 어려울 만큼 늘어나는데 표 하나로 유지함. 서로 영향이 없는 조건끼리 표를 나누거나, 조건 사이 상호작용이 약하면 조합 테스트(페어와이즈)를 검토함

출처

섹션 제목: “출처”
  • ISTQB Certified Tester Foundation Level(CTFL) 실라버스 v4.0.1, 2024-09-15, 4.2.3 Decision Table Testing
  • ISO/IEC/IEEE 29119-4:2021 테스트 기법
  • ISO 표준 원문은 유료이며 링크는 ISO 공식 안내 페이지임

관련 문서

테스트 설계동등 분할시스템이 똑같이 처리할 것으로 기대되는 입력을 한 묶음(동등 클래스)으로 보고, 묶음마다 대표값 하나만 테스트하는 기법이다(Equivalence Partitioning).테스트 설계경계값 분석처리 결과가 달라지는 경계와 그 바로 안팎의 값을 선택해 테스트하는 기법이다(Boundary Value Analysis).테스트 설계조합 테스트(페어와이즈)파라미터가 여러 개일 때 모든 조합을 수행하지 않고, 임의의 두 파라미터 값 쌍이 모두 한 번 이상 포함되도록 테스트 집합을 구성하는 기법이다(Pairwise Testing). 두 파라미터를 넘는 상호작용까지 보장하는 기법은 t-way 조합 테스트라고 한다.테스트 설계상태 전이 테스트대상이 가질 수 있는 상태와 상태를 변경하는 사건을 정리한 뒤, 허용된 전이와 차단되어야 하는 전이를 모두 테스트하는 기법이다(State Transition Testing).도메인별보안 테스트의 기본 관점접근 제어, 인증과 세션, 입력 처리, 비밀값 노출, 보안 설정에서 권한 없는 동작과 정보 노출이 발생하지 않는지 확인하는 테스트다. OWASP Top 10, ASVS, WSTG를 점검 기준으로 사용한다.

경계값 분석

처리 결과가 달라지는 경계와 그 바로 안팎의 값을 선택해 테스트하는 기법이다(Boundary Value Analysis).

기본기난이도 기초최종 업데이트 2026-11-24

결함은 범위의 한가운데보다 경계에서 자주 발생한다. <와 <=를 혼동하거나 끝 인덱스를 하나 덜 세는 실수는 경계값에서만 확인된다.

선택하는 값

섹션 제목: “선택하는 값”

경계값은 각 동등 분할의 최솟값과 최댓값이다. 유효 분할뿐 아니라 무효 분할의 최솟값과 최댓값도 경계값이다. 최댓값이 없는 분할(예: 65자 이상)은 경계값이 하나다.

  • 2값 방식: 경계값마다 경계값 자신과, 이웃한 분할에 속한 가장 가까운 값. 결과적으로 모든 분할의 경계값을 수행함
  • 3값 방식: 경계값마다 경계값 자신과 양쪽 이웃. 이웃이 어느 분할에 속하든 포함함
  • 정의역에 없는 값(예: 길이 -1)은 커버리지 항목에서 제외함
  • 경계 안팎 값의 간격은 데이터 형식에 따라 결정함
    • 정수: 1
    • 금액: 최소 화폐 단위
    • 날짜: 하루
    • 실수: 비교에 사용하는 정밀도의 최소 단위

예: 비밀번호 길이 8~64자

  • 분할: 0~7자(거부), 8~64자(허용), 65자 이상(거부)
  • 경계값: 0자, 7자, 8자, 64자, 65자
  • 2값 방식: 0자, 7자, 8자, 64자, 65자
  • 3값 방식: 0자, 1자, 6자, 7자, 8자, 9자, 63자, 64자, 65자, 66자. 0자의 아래 이웃(-1자)은 존재하지 않아 제외함

숫자가 아닌 경계

섹션 제목: “숫자가 아닌 경계”
  • 문자열: 빈 문자열, 공백만 있는 문자열, 최대 길이, 다국어 문자(한 글자가 여러 바이트. 길이 제한이 문자 수 기준인지 바이트 수 기준인지 확인)
  • 목록: 0개, 1개, 페이지 크기와 같은 개수, 페이지 크기 + 1
  • 시간: 자정, 월말, 윤년 2월 29일, 시간대가 변경되는 시점, 휴장일(거래소가 쉬는 날) 다음 날
  • 권한: 역할 변경 직전과 직후, 만료 시각 직전과 직후

규칙

  • 경계는 명세에서 도출함. 명세에 범위가 없으면 경계값 TC를 임의로 작성하지 않고 확인 항목으로 기록함
  • 화면 입력 제한(maxlength) 확인만으로 통과로 판정하지 않음. 화면을 거치지 않고 같은 값을 API로 직접 전송해 서버 차단 여부도 확인함

TC 예시

섹션 제목: “TC 예시”
경계 TC 예시
문자열 길이 상한(명세: 64자) 64자 비밀번호로 가입하면 계정이 생성되고, 65자로 가입하면 명세의 길이 오류 문구가 표시되며 계정이 생성되지 않는지 확인함
서버 측 상한 화면 입력 제한을 거치지 않고 65자 값을 API로 직접 전송해 400과 오류 필드가 반환되고 값이 저장되지 않는지 확인함
날짜 범위(예: 예약 가능일은 오늘부터 30일 이내) 테스트 시각을 고정한 환경에서 오늘, 오늘 + 30일은 예약되고 오늘 - 1일, 오늘 + 31일은 거부되는지 확인함. 기준 시간대를 TC에 명시함
목록 페이지(예: 페이지 크기 20) 데이터 20건 조건에서 1페이지에 20건이 표시되고 다음 페이지가 없으며, 21건 조건에서 2페이지에 1건이 표시되고, 1페이지 마지막 항목과 2페이지 첫 항목의 정렬 키가 중복·누락 없이 이어지는지 확인함
만료 시각(예: 세션 타임아웃 30분) 시각을 조작할 수 있는 환경에서 세션 두 개를 따로 준비해, 마지막 요청 후 29분 59초에 보낸 요청은 성공하고 30분 1초에 보낸 요청은 401이 반환되는지 확인함. 앞선 성공 요청이 유휴 시간을 갱신하므로 같은 세션으로 연달아 확인하지 않음
다국어 길이(예: 문자 수 기준 20자) 한글 20자는 저장되고 21자는 거부되는지, 화면의 글자 수 표시와 서버 판정이 같은 기준으로 계산되는지 확인함
0건 결과가 0건인 조건으로 검색해 명세의 빈 결과 문구가 표시되고 오류 문구나 빈 화면이 표시되지 않는지 확인함

적용 예: 게시글 첨부 파일 업로드

섹션 제목: “적용 예: 게시글 첨부 파일 업로드”

요구사항이 “게시글에 파일을 최대 5개, 파일당 10MB까지 첨부할 수 있다.” 한 줄인 경우, 먼저 동등 분할로 입력을 묶고 묶음 사이의 경계를 선택한다.

동등 분할 결과

  • 첨부 개수: 0개(첨부 없음), 1~5개(허용), 6개 이상(거부)
  • 파일 크기: 0바이트, 1바이트~10MB(허용), 10MB 초과(거부)

이 단계에서 명세로 답할 수 없는 질문이 나온다. 기획과 확인한 뒤 경계를 확정한다.

  • 10MB의 정의: 10,485,760바이트(10 × 1024 × 1024)인지 10,000,000바이트인지
  • 0바이트 파일의 허용 여부
  • 게시글 수정 화면에서 기존 첨부의 개수 포함 여부
  • 4개가 첨부된 상태에서 2개를 한 번에 선택했을 때 전부 거부하는지, 1개만 추가하는지

10MB를 10,485,760바이트로 확정했다고 가정하면 2값 방식으로 도출되는 TC는 다음과 같다. 경계값은 첨부 개수 0, 1, 5, 6개와 파일 크기 1, 10,485,760, 10,485,761바이트다.

  • 첨부 0개로 게시글을 등록해 첨부 없이 저장됨
  • 1개를 첨부해 등록하면 1개가 저장됨
  • 5개를 첨부해 등록하면 5개 모두 저장되고, 6번째 파일을 선택하면 개수 초과 문구가 표시되며 추가되지 않음
  • 1바이트 파일과 10,485,760바이트 파일은 업로드되고 10,485,761바이트 파일은 크기 초과 문구가 표시되며 업로드되지 않음. 0바이트 파일은 허용 여부를 확정한 뒤 추가함
  • 첨부 5개가 있는 게시글의 수정 화면에서 파일 1개를 추가하면 개수 초과 문구가 표시됨
  • 화면을 거치지 않고 API로 6번째 파일과 10,485,761바이트 파일을 각각 전송하면 400이 반환되고 저장되지 않음

개수 경계에는 한 번에 선택한 개수와 누적 개수라는 두 경로가 있다. 경로마다 경계를 따로 확인해야 수정 화면의 누락을 찾을 수 있다.

테스트 계획, 결함 분류, 보고에 적용

섹션 제목: “테스트 계획, 결함 분류, 보고에 적용”

테스트 계획

  • 입력 항목마다 명세의 경계와 값 간격(문자, 바이트, 원, 일)을 표로 정리해 계획서에 첨부함
  • 명세에 없는 경계는 확인 항목 목록으로 분리하고, 확정 전까지 TC로 작성하지 않음
  • 항목별로 2값 방식과 3값 방식 중 하나를 지정함. 예: 금액, 권한, 만료처럼 결함 영향이 큰 항목은 3값 방식
  • 화면 검증과 서버 검증을 별도 범위로 계획함

결함 분류

  • 결함 기록에 경계값과 바로 안팎 값의 결과를 함께 기록함. 예: “64자 허용, 65자 허용(거부 기대), 66자 거부”. 실제 경계가 어디로 이동했는지가 남아 원인을 좁힐 수 있음
  • 원인 유형을 비교 연산자 오류, 단위·정의 불일치(문자 수와 바이트 수, MB 정의, 시간대), 화면과 서버 판정 불일치로 나눠 라벨로 기록함

보고

  • 경계값 커버리지는 수행한 커버리지 항목 수를 식별한 항목 수로 나눈 값임. 2값 방식은 경계값, 3값 방식은 경계값과 양쪽 이웃 값이 항목임(ISTQB CTFL v4.0.1)
  • 보고서에는 수치와 함께 미수행 경계와 그 사유를 기록함. 예: “식별한 경계값 18개 중 16개 수행, 2개는 명세 확인 대기(0바이트 파일, 수정 화면의 누적 개수)”

현장 노트

  • 주가 지표 RSI(상대강도지수) 계산에서 평균 손실이 0이면 RS(평균 상승 / 평균 손실)를 100으로 고정하는 분기 하나로 처리해, 하락이 없는 구간은 100 대신 99.01, 완전 횡보 구간은 중립값 50 대신 99.01로 계산됨. AI 교차 검증으로 발견했고, 평탄 50, 하락 없음 100, 상승 없음 0으로 경계 규약을 정리함
  • 외부 목록 API의 index 파라미터를 오프셋으로 가정하고 page * size를 전달함. 연속한 두 페이지의 정렬 키를 비교해 index가 페이지 번호임을 확인함(index=30에서 약 한 달 치를 건너뜀). 건너뛴 구간을 이전 수집기가 이미 채워 두어 수집 결과에서는 공백이 확인되지 않았고, 수정 후 다시 수집하자 특정 일자의 항목이 13건에서 30건으로 늘어남. 같은 API의 페이지 크기 상한은 50이었고 60을 보내면 HTTP 400이 반환됨
  • 외부 API가 발급 후 6시간 안의 재요청에 같은 토큰을 반환하고, 그 토큰의 수명은 첫 발급 + 24시간이었음. 다른 작업이 먼저 발급받은 토큰을 배치가 다시 받으면서 캐시에 “받은 시각 + 23시간”을 만료로 기록해, 캐시상 유효한 토큰이 서버에서 만료되어 배치가 실패함. 캐시 기록 위치를 하나로 모으고, 서버가 응답한 만료 시각에서 1시간을 뺀 값을 기록하도록 수정함. 만료 경계를 TC로 작성할 때는 기준 시각(첫 발급인지 재요청인지)을 함께 정함

흔한 실수

섹션 제목: “흔한 실수”
  • 유효 범위의 양 끝과 그 바깥값만 경계로 보고, 무효 분할의 경계값(문자열 길이의 0자 등)과 3값 방식의 바깥쪽 이웃(6자, 66자 등)을 빠뜨림
  • 단위 정의를 확인하지 않고 경계를 정함. 10MB, 20자, 30일의 계산 기준이 구현과 다르면 경계 TC가 모두 다른 값을 확인하게 됨
  • 시간 경계를 테스트 수행 시점의 실제 시각으로 확인함. 자정, 월말, 만료 경계는 시각을 고정하거나 조작할 수 있는 환경에서 확인함
  • 화면의 글자 수 표시나 입력 제한만 확인하고 서버 판정을 확인하지 않음
  • 목록 경계를 건수로만 확인하고 페이지 사이의 중복과 누락은 확인하지 않음

관련 문서

테스트 설계동등 분할시스템이 똑같이 처리할 것으로 기대되는 입력을 한 묶음(동등 클래스)으로 보고, 묶음마다 대표값 하나만 테스트하는 기법이다(Equivalence Partitioning).테스트 설계결정 테이블 테스트여러 조건의 조합에 따라 동작이 달라지는 규칙을 표로 정리하고, 표의 열마다 테스트 케이스를 도출하는 기법이다(Decision Table Testing). 명세의 누락과 모순을 설계 단계에서 찾는 데도 사용한다.테스트 설계리스크 기반 테스트실패했을 때의 피해와 실패할 가능성을 기준으로 무엇을 먼저, 얼마나 깊게 테스트할지 정하는 방식이다(Risk-Based Testing).

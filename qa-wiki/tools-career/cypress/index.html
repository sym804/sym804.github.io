Cypress

브라우저 안에서 테스트 코드를 실행하는 웹 테스트 도구 Cypress의 구조와 특성, 명령 체인과 비동기 큐, 재시도 가능한 단언, cy.intercept, 컴포넌트 테스트, cy.session, 다중 탭·다중 출처 제약, 지원 브라우저, Cypress Cloud의 기능 범위를 다룬다.

기본기난이도 중급웹 프론트엔드최종 업데이트 2026-11-24

Cypress는 JavaScript·TypeScript로 E2E 테스트와 컴포넌트 테스트를 작성하는 웹 테스트 도구다. 테스트를 실행하는 앱은 Cypress.io가 MIT 라이선스로 공개하고, 실행 기록과 병렬 실행을 제공하는 Cypress Cloud는 무료 플랜과 유료 플랜이 있는 별도 서비스로 운영한다. 2026-11 기준 최신 버전은 16.3.0(2026-11-10)이며 Node.js 22.x, 24.x, 26.x 이상이 필요하다.

브라우저 안에서 실행되는 구조

섹션 제목: “브라우저 안에서 실행되는 구조”

Cypress의 테스트 코드는 테스트 대상 앱과 같은 브라우저 안에서 실행된다. 공식 문서의 Trade-offs 절은 이 구조에서 나오는 영구적인 제약과 일시적인 제약을 구분해 설명한다.

영구적인 제약

  • 범용 자동화 도구가 아님. 공식 문서는 직접 개발하는 앱의 테스트를 주 용도로 둠
  • 서버 측 코드를 테스트 코드에서 바로 import할 수 없음. DB 초기화 같은 서버 작업은 cy.task()(Node 프로세스에서 실행)나 cy.request()(HTTP 요청)로 수행함
  • 브라우저 두 개를 동시에 조작할 수 없음. 공식 문서는 협업 기능을 스텁이나 별도의 백그라운드 클라이언트로 테스트하도록 안내함
  • 테스트 하나는 하나의 superdomain에 묶임. 다른 출처로 이동하는 단계는 cy.origin()으로 작성함

일시적인 제약(향후 바뀔 수 있음)

  • cy.hover() 명령이 없음. 공식 문서가 우회 방법을 안내함
  • 대부분의 조작 명령은 브라우저 기본 이벤트(native event)가 아니라 JavaScript로 이벤트를 흉내 냄. 단일 키 입력용 cy.press()는 예외임
  • iframe 지원이 제한적임. 같은 출처의 iframe은 조회할 수 있지만 iframe으로 전환하는 명령은 아직 제안 단계임

명령 체인과 비동기 큐

섹션 제목: “명령 체인과 비동기 큐”

Cypress 명령은 호출 즉시 실행되지 않는다. 명령은 큐에 추가된 뒤 바로 반환되고, 테스트 함수가 끝난 뒤 큐의 순서대로 실행된다.

  • 명령은 Promise가 아니라 await로 기다릴 수 없음
  • 명령의 반환값을 변수에 담아 사용할 수 없음. 명령은 결과를 반환하지 않고 다음 명령에 주체(subject)로 넘김(yield)
  • cy.get()은 DOM 요소를, .click()은 받은 주체를 그대로, cy.clearCookies()는 null을 다음 명령에 넘김
  • 실제 값이 필요하면 .then() 콜백에서 주체를 받거나 별칭(.as())을 사용함

재시도 가능한 단언

섹션 제목: “재시도 가능한 단언”
구분 동작
쿼리(cy.get(), .find() 등) 재시도함. 이어진 쿼리는 체인 전체를 처음부터 다시 실행함
단언(.should()) 실패하면 앞의 쿼리를 다시 실행하고 다시 확인함. 여러 단언은 순서대로 통과해야 함
조작(.click(), .type() 등) 조작 자체는 한 번만 실행하고 재시도하지 않음. 실행 전에 요소가 조작 가능한 상태가 될 때까지 기다림
  • 재시도 시간은 defaultCommandTimeout(기본 4초)임. cy.visit(), cy.task()처럼 기본값이 60초인 명령도 있음
  • timeout은 단언이 아니라 명령에 지정함(cy.get(sel, { timeout: 10000 })). timeout: 0이면 재시도하지 않음
  • 공식 문서는 조작을 체인의 중간이 아니라 끝에 두라고 권고함. 조작 뒤에는 새 체인으로 나눠 씀
  • 체인 중간의 단언이 통과하면 그 시점의 주체가 고정됨. 이후 화면이 다시 렌더링되면 고정된 요소가 DOM에서 분리될 수 있어 체인을 나누거나 .should(콜백)을 사용함
  • .then()은 재시도하지 않음. 값 확인은 .should()로 작성함
  • 고정 대기 cy.wait(숫자) 대신 라우트 별칭이나 단언으로 기다릴 조건을 명시함

주요 기능

섹션 제목: “주요 기능”

cy.intercept

섹션 제목: “cy.intercept”

네트워크 요청을 감시(spy)하거나 응답을 대체(stub)하는 명령이다. 응답 인자 없이 정의하면 감시만 하고, 정적 응답(StaticResponse)이나 핸들러 함수를 주면 응답을 대체한다.

  • 일치 조건: 메서드(생략하면 모든 메서드), URL 문자열·glob·정규식, routeMatcher 객체(hostname, pathname, query, headers, times)
  • 정적 응답: statusCode(기본 200), body, headers, fixture(fixtures 폴더의 파일), forceNetworkError, delay, throttleKbps
  • 대기: .as('이름')으로 별칭을 붙이고 cy.wait('@이름')으로 요청 완료를 기다린 뒤 요청과 응답을 단언함
  • 핸들러: req.reply()는 서버에 보내지 않고 응답하고, req.continue()는 서버로 보낸 뒤 콜백에서 실제 응답을 변경함
  • 모든 intercept는 테스트마다 자동으로 초기화됨. 여러 라우트가 일치하면 나중에 정의한 라우트부터 처리함
  • 16.0.0부터 Chrome, Chromium, Edge는 브라우저 기본 네트워크 경로에서 가로챔. 이 경로에서는 req.httpVersion이 보고되지 않음
  • 옛 명령 cy.server(), cy.route()는 6.0.0에서 폐기 예정으로 바뀌고 12.0.0에서 제거됨. 대체 명령이 cy.intercept()임

세션 캐시(cy.session)

섹션 제목: “세션 캐시(cy.session)”

cy.session(id, setup, options)은 로그인 후의 쿠키, localStorage, sessionStorage를 id 기준으로 캐시하고 다음 테스트에서 복원한다. setup은 캐시가 없을 때만 실행된다.

  • validate: 세션이 유효한지 확인하는 함수. 복원한 세션의 검증이 실패하면 세션을 지우고 setup을 다시 실행함. setup 직후의 검증이 실패하면 테스트가 실패함
  • cacheAcrossSpecs: true: 같은 실행 안의 다른 spec 파일에서도 세션을 복원함. 캐시는 그 실행의 메모리에만 있음
  • 테스트 격리(testIsolation, E2E 기본값 true): 테스트마다 about:blank로 이동하고 모든 도메인의 쿠키, localStorage, sessionStorage를 지움. IndexedDB는 지우지 않음. 그래서 setup 안에서 필요한 페이지를 직접 방문해야 함
  • 컴포넌트 테스트는 격리 설정을 바꿀 수 없고, 테스트마다 컴포넌트를 해제하고 저장소를 지움

cy.env()는 요청한 키의 값만 Node 프로세스에서 받아 오고 명령 로그에는 이름만 남긴다. 받아 온 객체 자체는 마스킹되지 않으므로 비밀번호 입력에는 { log: false }를 함께 지정한다. 공개해도 되는 값은 동기 함수 Cypress.expose()로 읽는다.

컴포넌트 테스트

섹션 제목: “컴포넌트 테스트”

URL을 방문하지 않고 cy.mount()로 컴포넌트 하나를 실제 브라우저에 마운트해 테스트하는 방식이다. 외부 시스템에 의존하지 않아 빠르고 설정이 쉽지만, 앱의 여러 계층이 함께 동작하는지는 확인하지 않는다. 공식 문서는 E2E와 컴포넌트 테스트를 함께 사용하도록 권한다.

Next.js 15~16 Webpack 5
Vue 3 Vite 8, Webpack 5

다중 탭과 다중 출처

섹션 제목: “다중 탭과 다중 출처”
  • 탭과 팝업: 같은 브라우저 안에서 새 탭이나 팝업을 여는 흐름은 @cypress/puppeteer 플러그인으로 테스트함. 링크가 열리는지만 확인하면 두 번째 탭이 필요 없음. 플러그인은 Chromium 계열 브라우저에서만 동작하고 Firefox, WebKit은 지원하지 않음. Electron은 Puppeteer로 새 탭을 여는 browser.newPage()를 지원하지 않지만 앱이 직접 여는 탭과 창은 다룰 수 있음. Google Chrome 137 이상은 헤드 모드(headed) 실행을 지원하지 않아 Chrome for Testing, Chromium, Electron을 사용하거나 헤드리스로 실행함
  • 다른 출처: cy.origin(url, { args }, 콜백)으로 다른 출처의 페이지에서 명령을 실행함. 출처는 스킴, 호스트 이름, 포트로 정해지므로 하위 도메인도 다른 출처임
  • cy.origin() 제약: args 값은 직렬화할 수 있어야 하고 함수와 DOM 요소는 넘어가지 않음. 콜백 안에서 cy.intercept(), cy.session(), cy.origin()을 호출하면 오류가 발생함. intercept는 콜백 밖에서 먼저 등록함. 실험 기능인 WebKit에서는 지원하지 않음
  • injectDocumentDomain: true로 출처 대신 superdomain을 비교하는 방식은 폐기 예정임

지원 브라우저

섹션 제목: “지원 브라우저”
  • Chrome 계열: Chrome for Testing, Chrome(Beta, Canary), Chromium
  • Edge 계열: Edge(Beta, Canary, Dev)
  • Firefox 계열: Firefox(Developer Edition, Nightly). 140 미만은 지원하지 않음
  • Electron: 기본 브라우저이지만 폐기 예정이며 향후 버전에서 제거됨. 공식 문서는 defaultBrowser를 지정하고 --browser를 명시하도록 권함
  • WebKit: 실험 기능. experimentalWebKitSupport: true와 playwright-webkit 설치가 필요함. Safari 자체는 지원하지 않으며 cy.origin(), Test Replay를 사용할 수 없음
  • cypress run은 기본적으로 헤드리스로 실행하고 cypress open은 항상 화면을 표시함

Cypress Cloud

섹션 제목: “Cypress Cloud”

cypress run 결과를 기록해 분석하는 서비스다. 무료 플랜(Starter)과 유료 플랜이 있고, 플랜마다 사용자 수, 월 테스트 결과 수, 기능이 다르므로 요금 페이지에서 확인한다. 기능 범위는 다음과 같다.

  • 실행 기록과 Test Replay(기록한 실행을 디버깅 도구와 함께 재현)
  • Smart Orchestration: 여러 머신에 spec을 나눠 병렬 실행하고 부하를 분산함. 최근 실패한 spec 우선 실행, 실패 시 자동 취소
  • Flaky Test Management와 테스트 상태 분석
  • GitHub, GitLab, Bitbucket, Slack, Microsoft Teams, Jira 연동
  • UI Coverage, Cypress Accessibility(추가 유료 기능)

QA에서 사용하는 방법

섹션 제목: “QA에서 사용하는 방법”
  • 선택자: 공식 문서는 CSS나 JS 변경과 분리된 data-* 속성(예: data-cy)을 권장하고, id, class, 태그, 바뀔 수 있는 텍스트를 기준으로 찾지 말라고 안내함. 개발팀과 속성 이름 규칙을 합의함(테스트 자동화 기본의 테스트 용이성)
  • 테스트 데이터: UI 로그인을 반복하지 않고 cy.session()으로 캐시하며, 사전 데이터는 cy.request()나 cy.task()로 생성함. 테스트는 it.only로 단독 실행해도 통과해야 함
  • 서버 실행: 공식 문서는 Cypress 안에서 백엔드 서버를 실행하지 말고, 실행 전에 서버를 띄우고 실행 후 종료하도록 권고함. 빌드 산출물을 서빙하는 구성은 E2E 테스트 전 빌드를 따름
  • 재시도: retries 기본값은 실행 모드(runMode)와 대화형 모드(openMode) 모두 0임. 재시도에서 통과한 테스트는 Cypress Cloud에서 Flaky로 표시됨. 집계 기준은 Flaky 테스트 관리를 따름
  • 실패 분류: 실패 시 스크린샷(screenshotOnRunFailure 기본 true)을 근거로 분류함. 동영상(video)은 기본값 false라 필요하면 켬(E2E 실패 분류)
  • 시각 비교: cy.screenshot()은 캡처만 하고 이미지를 비교하지 않음. 공식 문서는 오픈소스 플러그인이나 상용 서비스와 조합하고, 렌더링 환경을 고정하고, 전체 페이지보다 개별 요소를 캡처하도록 안내함(시각 회귀 테스트)
  • CI 연동은 GitHub Actions, Jenkins 문서를 따름

여러 브라우저·탭 브라우저 하나만 조작함. 탭은 플러그인 사용 컨텍스트와 페이지를 여럿 생성함 창 핸들로 탭과 창을 전환함

선택 기준

  • 프론트엔드 개발자가 JavaScript로 컴포넌트 테스트와 E2E를 같은 도구로 작성하는 팀이면 Cypress가 맞음
  • 한 테스트에서 두 사용자(두 브라우저)가 상호작용하는 시나리오, Safari 엔진 확인, 여러 출처를 오가는 흐름이 많으면 Playwright나 Selenium의 지원 범위를 먼저 확인함
  • Java, C#, Python 팀이면 해당 언어 바인딩이 있는 Selenium이나 Playwright를 검토함
  • Cypress의 병렬 실행 배분(Smart Orchestration)과 실행 기록은 Cypress Cloud가 제공함. 외부 서비스에 실행 기록을 보낼 수 없는 조직이면 대체 구성을 먼저 정함
  • 같은 시나리오로 파일럿을 수행해 실행 시간, 실패 분석 시간, 유지 비용을 비교함(테스트 자동화 기본)

주의할 점

섹션 제목: “주의할 점”
  • async/await나 변수 대입으로 명령 결과를 다루면 의도와 다른 순서로 실행됨. 주체 전달과 .then(), 별칭으로 작성함
  • 조작 명령은 JavaScript 이벤트를 흉내 내므로 브라우저 기본 이벤트에서만 발생하는 결함은 재현되지 않을 수 있음
  • CI에서 브라우저를 지정하지 않으면 폐기 예정인 Electron으로 실행됨. 대상 브라우저를 명시하고 결함 보고에 브라우저와 버전을 기록함
  • 16.0.0에서 Cypress.env()가 제거되어 Cypress.expose()(공개 값)나 cy.env()(비밀 값)로 바꿔야 함. cy.exec()는 제거되어 cy.task()로 대체하고, cy.end()는 삭제함. cy.type()의 기본 keystrokeDelay가 10에서 0으로 바뀜
  • cy.getCookie(), cy.getCookies() 등 쿠키·저장소 조회 명령이 16.0.0부터 재시도 쿼리가 되어 Cypress.Commands.overwrite()로 덮어쓸 수 없음. overwriteQuery()를 사용함
  • 비밀 값을 cy.env()로 받아도 단언, .its(), .invoke()의 로그에는 값이 표시될 수 있음

관련 문서

자동화테스트 자동화 기본테스트 자동화는 도구로 테스트를 실행하고 결과를 판정하는 활동이다. 이점과 한계, 테스트 피라미드, 테스트 용이성, 자동화 아키텍처(gTAA)와 프레임워크 계층, 케이스 자동화 방식 7가지, 도입 절차와 파이프라인 배치, 작성 원칙을 ISTQB CTAL-TAE 기준으로 설명한다.자동화Flaky 테스트 관리코드와 환경이 같은데도 실행마다 결과가 달라지는 테스트(Flaky 테스트)의 원인을 분류하고 탐지, 격리, 수정하는 절차다.자동화E2E 실패 분류Playwright 실패를 산출물 근거로 원인별로 분류하는 방법. 원인 분류 체계를 고르는 기준, 결과 상태 확인, 산출물 확인, 재현 순서, 결과 기록 기준을 다룬다. 분류는 수정보다 먼저 수행한다.자동화시각 회귀 테스트화면 캡처를 베이스라인과 비교해 의도하지 않은 화면 변화를 검출하는 테스트다. 캡처 환경, 허용 오차, 베이스라인 갱신 절차를 고정해야 결과를 판정 근거로 사용할 수 있다.

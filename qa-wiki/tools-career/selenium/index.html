Selenium

웹 브라우저 자동화 프로젝트 Selenium의 구성(WebDriver, Grid, IDE)과 핵심 개념(W3C WebDriver 표준, 브라우저 드라이버와 Selenium Manager, 언어 바인딩, 로케이터 전략, 명시적·암묵적 대기, 페이지 객체 모델, WebDriver BiDi), 옛 API 정리, QA 적용 방법을 다룬다.

기본기난이도 중급웹 프론트엔드최종 업데이트 2026-11-24

Selenium은 웹 브라우저 자동화를 위한 도구와 라이브러리를 묶은 오픈소스(Apache-2.0) 프로젝트다. GitHub의 SeleniumHQ 조직에서 자원 기여자들이 개발한다. 브라우저를 조작하는 WebDriver, 여러 머신에서 병렬로 실행하는 Grid, 조작을 기록하고 재생하는 IDE로 구성된다. 2026-11 기준 최신 안정 버전은 4.53.0(2026-11-17)이고, 언어 바인딩과 Grid 서버가 같은 버전으로 배포된다.

핵심 개념

섹션 제목: “핵심 개념”
개념 뜻
WebDriver 브라우저를 사용자가 조작하듯 직접 제어하는 인터페이스. 로컬 브라우저나 Selenium 서버를 거친 원격 브라우저를 조작함. Selenium WebDriver는 언어 바인딩과 브라우저별 제어 구현을 함께 가리킴
W3C WebDriver 표준 브라우저 원격 제어를 위한 플랫폼·언어 중립 프로토콜. WebDriver(Level 1)는 2018-06-05에 W3C 권고안(Recommendation)이 되었고, 후속판 WebDriver(webdriver2)는 2026-11 기준 작업 초안(Working Draft)임
언어 바인딩 테스트 코드에서 WebDriver를 호출하는 라이브러리. Java, Python, C#(.NET), Ruby, JavaScript를 공식 배포하고, Kotlin은 Java 바인딩을 사용함
브라우저 드라이버 브라우저별 WebDriver 구현. Chrome은 Google의 chromedriver, Firefox는 Mozilla의 geckodriver, Edge는 Microsoft 드라이버, Safari는 Apple이 OS에 내장한 드라이버, Internet Explorer는 Selenium 프로젝트의 드라이버(Windows 전용, 레거시)
Selenium Manager 설치된 브라우저 버전에 맞는 드라이버를 찾아 내려받고 캐시하는 도구
창 핸들(window handle) 세션 안에서 창과 탭을 식별하는 고유 값. WebDriver는 창과 탭을 구분하지 않음

브라우저 드라이버와 Selenium Manager

섹션 제목: “브라우저 드라이버와 Selenium Manager”

4.6부터 Selenium Manager가 바인딩에 포함되어, 드라이버 경로를 지정하지 않으면 자동으로 동작한다.

  • 드라이버 관리: 설치된 브라우저 버전을 확인하고 맞는 드라이버를 내려받아 캐시함
  • 브라우저 관리: 브라우저가 없으면 내려받음. Chrome(Chrome for Testing)은 4.11.0, Firefox는 4.12.0, Edge는 4.14.0부터 지원함. Windows에서 Edge 설치는 관리자 권한이 필요함
  • 대체 수단으로만 동작함: 드라이버 경로를 직접 지정하거나 PATH에 드라이버가 있으면 사용하지 않음
  • 캐시 위치: 기본값 ~/.cache/selenium. SE_CACHE_PATH 환경 변수로 변경함
  • 상태: 공식 문서 기준 베타이며 자체 버전은 0.x임

드라이버 위치를 직접 지정할 때는 서비스 객체를 사용한다(Python webdriver.ChromeService(executable_path=...), Java ChromeDriverService.Builder().usingDriverExecutable(...)).

로케이터 전략

섹션 제목: “로케이터 전략”

find_element(Java findElement)는 일치하는 첫 요소를, find_elements는 일치하는 모든 요소를 반환한다. 전통적인 로케이터는 8가지다.

전략 찾는 기준
id id 속성
name name 속성
class name 클래스 이름
css selector CSS 선택자
xpath XPath 식
link text 링크의 전체 텍스트
partial link text 링크 텍스트 일부. 여러 개가 일치하면 첫 요소만 선택함
tag name 태그 이름

공식 권장 순서

  • 고유하고 예측 가능한 id가 있으면 id를 우선 사용함. 빠르게 동작함
  • id가 없으면 잘 작성한 CSS 선택자를 사용함
  • XPath는 CSS만큼 동작하지만 문법이 복잡해 디버깅이 어렵고, 브라우저 공급사가 XPath 성능을 따로 테스트하지 않는 경우가 많아 느린 경향이 있음
  • link text는 링크 요소에만 동작함. tag name은 같은 태그가 많아 단일 요소 탐색에 위험함
  • 탐색 범위를 좁힘. 부모 요소를 먼저 찾은 뒤 그 요소에서 다시 찾거나(form.find_element(...)), 한 번의 CSS 선택자(form .information)로 찾음

이 밖에 다른 요소를 기준으로 위(above), 아래(below), 근처(near) 같은 상대 위치로 찾는 상대 로케이터(Relative Locators)가 있다. Playwright의 getByRole 같은 접근성 역할 기반 로케이터는 Selenium의 기본 전략에 없다.

대기

섹션 제목: “대기”

브라우저 자동화가 실패하는 흔한 원인은 페이지가 준비되기 전에 다음 명령이 실행되는 경합 상태(race condition)다. 고정 대기(sleep)는 짧으면 실패하고 길면 실행이 느려진다.

  • 암묵적 대기(implicit wait): 세션 전체에 적용하는 설정. 요소 탐색마다 요소가 나타날 때까지 기다림. 기본값은 0이라 요소가 없으면 즉시 오류가 발생함(Python driver.implicitly_wait(2))
  • 명시적 대기(explicit wait): 코드에 추가하는 폴링. 필요한 지점에서 특정 조건이 참이 될 때까지 확인하고 timeout이 지나면 오류를 발생시킴(Python WebDriverWait)
  • 대기 설정 변경: 폴링 간격, timeout, 무시할 예외, 오류 메시지를 지정함. Java는 FluentWait, Python은 poll_frequency, ignored_exceptions를 사용함

공식 문서는 암묵적 대기와 명시적 대기를 섞어 쓰지 말라고 경고한다. 대기 시간을 예측할 수 없게 되며, 암묵적 대기 10초와 명시적 대기 15초를 함께 설정하면 20초 뒤에 timeout이 발생할 수 있다는 예를 든다.

quit()은 모든 창, 브라우저, 드라이버 프로세스를 종료한다. 호출하지 않으면 프로세스와 포트가 남는다. close()는 현재 창만 닫으므로, 닫은 뒤에는 유효한 창 핸들로 전환해야 한다.

페이지 객체 모델

섹션 제목: “페이지 객체 모델”

페이지 객체는 화면별 로케이터와 조작을 한 클래스에 모아 테스트 코드와 분리한다. 화면이 바뀌면 페이지 객체 한 곳만 수정한다. Selenium 공식 문서의 지침은 다음과 같다.

  • 페이지 객체는 검증이나 단언을 하지 않음. 화면 상태에 대한 단언은 테스트가 수행함
  • 예외는 페이지가 제대로 로드되었는지 확인하는 검증 하나이며, 보통 생성자에서 수행함
  • 메서드는 다음 화면의 페이지 객체나 자기 자신을 반환함. 화면 흐름이 바뀌면 반환 타입이 바뀌어 영향받는 테스트가 컴파일 단계에서 드러남(Java 등 정적 타입 언어)

계층 구조와 다른 패턴(퍼사드, 플로 모델)은 테스트 자동화 기본에 있다.

Selenium Grid

섹션 제목: “Selenium Grid”

Grid는 클라이언트가 보낸 명령을 원격 브라우저로 전달해 여러 머신(노드)에서 테스트를 병렬로 실행한다. 여러 브라우저 종류와 버전, 여러 OS 조합을 확인하고 스위트 실행 시간을 줄이는 데 사용한다. Grid 서버는 Selenium Server(jar)로 배포된다.

구성 요소 역할
Router Grid의 진입점. 외부 요청을 받아 맞는 구성 요소로 전달함
Distributor 노드를 등록·추적하고 새 세션 요청에 맞는 노드를 찾음
Session Map 세션 ID와 그 세션을 실행하는 노드의 관계를 저장함
New Session Queue 새 세션 요청을 FIFO 순서로 보관함
Node 실행 중인 머신의 브라우저 슬롯을 관리함
Event Bus 노드, Distributor, New Session Queue, Session Map 사이의 통신 경로

WebDriver BiDi

섹션 제목: “WebDriver BiDi”

기존 WebDriver(Classic)는 요청과 응답만 주고받는다. WebDriver BiDi는 WebSocket 연결을 추가한 양방향 프로토콜이라 네트워크 요청, 콘솔 메시지, JavaScript 오류 같은 브라우저 이벤트를 발생 시점에 받는다. Selenium 프로젝트가 브라우저 공급사와 함께 만들었고, W3C 문서는 2026-11 기준 작업 초안이다.

  • Selenium 문서는 BiDi를 Chrome DevTools Protocol(CDP)의 브라우저 간 대체 수단으로 설명하고, CDP 지원은 BiDi 구현이 끝날 때까지의 임시 지원이라고 밝힘
  • Selenium은 하위 호환을 최대한 유지하면서 구현 전체를 Classic에서 BiDi로 옮기는 중임
  • 문서는 기능을 로그 수신, 네트워크, 스크립트 영역으로 나눠 설명함
  • 켜는 방법: Java options.setCapability("webSocketUrl", true), Python options.enable_bidi = True

Selenium IDE

섹션 제목: “Selenium IDE”

현재 IDE는 브라우저 조작을 기록하고 재생하는 Windows, macOS, Linux용 단독 실행 애플리케이션(Electron 기반)이다. GitHub 릴리즈나 npm install -g selenium-ide로 설치한다. 이전 브라우저 확장판(버전 3)은 더 이상 유지보수되지 않고 Chrome 웹 스토어에서 내려갔으며, Firefox와 Edge 확장 스토어에는 남아 있다. 기록·재생 방식의 장단점은 테스트 자동화 기본의 캡처·재생 항목을 따른다.

옛 API와 현재 API

섹션 제목: “옛 API와 현재 API”

Selenium 4로 올리면서 제거되거나 폐기된 API가 있다. 오래된 예제를 그대로 사용하지 않는다.

구분 옛 API 현재
요소 찾기 Java findElementById, findElementsByClassName 등 driver.findElement(By.id(...)). 옛 메서드는 제거됨
대기 시간 Java implicitlyWait(10, TimeUnit.SECONDS) implicitlyWait가 Duration을 받음(예: Duration.ofSeconds(10)). WebDriverWait, FluentWait도 Duration을 받음
기능 지정 DesiredCapabilities 브라우저별 옵션 클래스(ChromeOptions 등). Python webdriver.Remote는 options=를 사용함
드라이버 경로 Python executable_path 생성자 인자 Service 객체
기능 이름 기능(capability) version, platform browserVersion, platformName. 비표준 기능은 공급사 접두어(예: cloud:options)를 붙임
브라우저 상수 Java BrowserType Browser
추가 옵션 C# AddAdditionalCapability AddAdditionalOption

QA에서 사용하는 방법

섹션 제목: “QA에서 사용하는 방법”
  • 크로스 브라우저 회귀: Grid 노드에 브라우저와 OS 조합을 구성해 같은 스위트를 병렬로 실행함. 조합 수를 줄이는 방법은 회귀 테스트 범위 선정을 따름
  • 결함 보고: 브라우저 버전, 드라이버 버전, Selenium 버전을 발생 환경에 기록함. Selenium Manager는 설치된 브라우저에 맞춰 드라이버를 내려받으므로, 브라우저가 업데이트되면 드라이버 버전도 달라짐(이슈 양식)
  • 실패 분류: 요소 탐색 실패는 대기 조건 누락(테스트 원인)과 화면 결함(제품 원인)을 구분해 분류함. 실패 시점의 스크린샷과 페이지 소스를 테스트 프레임워크의 실패 훅에서 저장하도록 구성함(E2E 실패 분류)
  • Flaky 관리: 고정 대기와 대기 방식 혼용을 원인 후보로 먼저 확인함(Flaky 테스트 관리)
  • 시각 회귀: Selenium에는 스크린샷 비교 단언이 내장되어 있지 않음. 별도 비교 도구나 서비스와 조합함(시각 회귀 테스트)
  • CI 연동: 테스트 러너(JUnit, pytest 등)의 리포트를 파이프라인 산출물로 보관함(Jenkins, GitHub Actions)

비슷한 도구와 선택 기준

섹션 제목: “비슷한 도구와 선택 기준”
항목 Selenium Playwright Cypress
유지 주체, 라이선스 Selenium 프로젝트(SeleniumHQ), Apache-2.0 Microsoft, Apache-2.0 Cypress.io, MIT(앱). Cypress Cloud는 무료·유료 플랜
언어 Java, Python, C#, Ruby, JavaScript JS·TS, Python, Java, .NET JS·TS
테스트 코드 실행 위치 브라우저 밖. WebDriver 프로토콜로 드라이버에 명령을 보냄 브라우저 밖의 워커 프로세스 브라우저 안. 앱과 같은 브라우저에서 실행됨
대기 명시적·암묵적 대기를 코드로 작성함 조작 전 자동 대기, 자동 재시도 단언 쿼리와 단언의 자동 재시도
테스트 러너 포함하지 않음. 언어별 테스트 프레임워크와 조합함 Playwright Test(Node.js) 내장
병렬 실행 Selenium Grid 내장 워커, 샤딩 Cypress Cloud의 Smart Orchestration

WebdriverIO는 OpenJS Foundation 산하 커뮤니티가 운영하는 오픈소스 프레임워크로, Selenium과 같은 W3C WebDriver와 WebDriver BiDi로 브라우저를 자동화한다.

선택 기준

  • Java, C#, Ruby 팀이거나 이미 WebDriver 기반 자산과 Grid 인프라가 있으면 Selenium을 유지하는 비용이 작음
  • 표준 프로토콜(W3C WebDriver)로 여러 공급사 브라우저를 같은 방식으로 조작해야 하는 경우 Selenium이나 WebdriverIO가 맞음
  • 대기와 리포트, 트레이스 같은 테스트 러너 기능을 한 도구에서 갖추려면 Playwright Test나 Cypress를 검토함
  • 모바일 앱 자동화는 Appium 문서를 함께 검토함
  • 같은 시나리오로 파일럿을 수행해 실행 시간, 실패 분석 시간, 유지 비용을 비교함(테스트 자동화 기본)

주의할 점

섹션 제목: “주의할 점”
  • 암묵적 대기와 명시적 대기를 함께 설정하지 않음. 한 프로젝트에서 한 방식을 정하고, 공통 라이브러리에 대기 함수를 모음
  • time.sleep, Thread.sleep 같은 고정 대기는 경합 상태를 해결하지 않음
  • quit()을 호출하지 않으면 CI 머신에 브라우저와 드라이버 프로세스가 남음. finally나 테스트 프레임워크의 정리 단계에서 호출함
  • 새 창을 여는 링크를 클릭해도 WebDriver의 포커스는 원래 창에 남음. 창 핸들로 전환한 뒤 조작함
  • Internet Explorer 드라이버는 문서의 레거시 영역에 있음. 새 테스트 대상에 포함하기 전에 지원 범위를 확인함
  • Selenium Manager는 베타 상태임. 재현성이 중요한 CI에서는 브라우저와 드라이버 버전을 기록하고, 필요하면 드라이버 경로를 직접 지정함
  • Selenium 3 기준으로 작성된 예제는 위 표의 제거·폐기 API를 사용함. 예제를 옮길 때 표와 대조함

관련 문서

자동화테스트 자동화 기본테스트 자동화는 도구로 테스트를 실행하고 결과를 판정하는 활동이다. 이점과 한계, 테스트 피라미드, 테스트 용이성, 자동화 아키텍처(gTAA)와 프레임워크 계층, 케이스 자동화 방식 7가지, 도입 절차와 파이프라인 배치, 작성 원칙을 ISTQB CTAL-TAE 기준으로 설명한다.자동화Flaky 테스트 관리코드와 환경이 같은데도 실행마다 결과가 달라지는 테스트(Flaky 테스트)의 원인을 분류하고 탐지, 격리, 수정하는 절차다.자동화E2E 실패 분류Playwright 실패를 산출물 근거로 원인별로 분류하는 방법. 원인 분류 체계를 고르는 기준, 결과 상태 확인, 산출물 확인, 재현 순서, 결과 기록 기준을 다룬다. 분류는 수정보다 먼저 수행한다.자동화시각 회귀 테스트화면 캡처를 베이스라인과 비교해 의도하지 않은 화면 변화를 검출하는 테스트다. 캡처 환경, 허용 오차, 베이스라인 갱신 절차를 고정해야 결과를 판정 근거로 사용할 수 있다.
